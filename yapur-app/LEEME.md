# Gestión YAPUR.NET — sin servidor propio

Todo corre gratis en Cloudflare (la cuenta donde ya está el Worker `favl`) y el APK lo arma GitHub, igual que la app de FAVL.

| Pieza | Dónde vive | Quién la arma |
|---|---|---|
| Sistema (clientes, planes, cobranzas, usuarios, base de datos) | `https://yapur.mauroyapur.workers.dev` | Cloudflare, desde la carpeta `yapur-app/worker` de este repositorio |
| APK para los celulares | `https://yapurnet.github.io/YAPUR-Gestion.apk` | GitHub Actions, firmado con la misma clave de FAVL |

El APK es solo una ventana que abre el sistema; **cuando se cambia el sistema no hace falta volver a instalar el APK**.

## Puesta en marcha (una sola vez)

1. **Aprobar el pedido de cambios** (Pull request) que trae esta carpeta: «Merge pull request». Hasta que esté en `main`, Cloudflare y GitHub no la ven.
2. **Cloudflare → Workers & Pages → Create → Import a repository** → GitHub → repositorio `yapurnet.github.io`.
   - Project name: `yapur` (tiene que ser exactamente ese, es el nombre que figura en `wrangler.jsonc`).
   - Root directory: `/yapur-app/worker`
   - Build command: dejar vacío. Deploy command: lo que proponga (`npx wrangler deploy`).
   - Opcional: en *Build watch paths* poner `yapur-app/worker/*` para que no se vuelva a publicar cuando se toca otra app del repositorio.
   - Cuando termina, la dirección es `https://yapur.<tu-subdominio>.workers.dev`. Si no es `mauroyapur`, editá `yapur-app/android/server-url.txt` con la dirección real antes de bajar el APK.
3. **Abrir esa dirección en el navegador**. Aparece la pantalla de instalación: poné el **código de instalación** que te pasé aparte (no está en ningún archivo del repositorio), tu usuario y una clave de 8 o más caracteres. Ese usuario es el administrador.
4. **Bajar el APK**: la pestaña *Actions* de GitHub corre sola «Compilar APK Gestión YAPUR» cuando entra el cambio (si no, *Run workflow*). A los 2-3 minutos queda en `https://yapurnet.github.io/YAPUR-Gestion.apk`. En el celular: abrir ese enlace, permitir «instalar de esta fuente» y listo. Como está firmado con la clave de FAVL, sin problemas si algún día se actualiza encima.
5. Desde **Ajustes → Usuarios** creás a la oficinista y a los técnicos con sus permisos.

## Pasar los datos que ya cargaste en la versión anterior (el Artifact)

1. En la versión vieja: **Ajustes → «Descargar copia para el servidor nuevo»** (se guarda un archivo `.json`).
2. En la nueva (ya con tu usuario administrador): **Ajustes → «Restaurar desde un archivo…»** y elegís ese archivo.
3. Los clientes existentes quedan con Ciclo 1 y sin servicios extra; ajustalos desde la ficha o con la importación.
4. El plan `Plan_15` quedó guardado a `$17` en la versión anterior: editarlo, poner `17.000` y tildar **«Es un error de carga»** (así vale para todos los meses).

## Cambios de precio, servicios nuevos y cambios de plan (vigencia por mes)

Un precio cambia **desde un mes**; los meses anteriores conservan lo que valían, así a quien ya pagó no le aparece deuda.

- **Aumento de un plan o de un servicio extra** (Planes → Editar): al cambiar el precio aparece *«El precio nuevo rige desde»* con el mes siguiente. Se puede elegir este mes o uno futuro. El plan muestra el aviso «Desde noviembre: $25.000» hasta que llega ese mes.
- **Error de carga** (por ejemplo `$17` en vez de `$17.000`): tildar *«Es un error de carga»* corrige todos los meses. Solo se ofrece mientras el plan no tenga aumentos anteriores; si ya los tiene, el cambio se carga con «rige desde».
- **Agregarle un servicio a un cliente, cambiarle el plan o ponerle precio especial** (ficha → Editar): aparece *«Los cambios rigen desde»* con este mes. Se puede elegir un mes anterior (por ejemplo si lo tenía desde antes), pero nunca antes de que empezara su situación actual. Lo anterior queda guardado como estaba.
- Vale lo mismo para quitar un servicio o volver al plan anterior. Si un cliente se corrige dentro del mismo mes que el cambio anterior, se toma como corrección y no se agrega historial.
- Los técnicos no reciben ni los precios ni este historial, y no pueden modificarlo.

## Ubicación de las casas con el GPS del celular

En la ficha del cliente, en «Cargar ubicación» y al terminar una orden de instalación hay un botón **«Usar mi ubicación actual (GPS)»**. Estando en el domicilio, el técnico lo toca, el celular toma lecturas unos segundos, se queda con la más precisa y completa las coordenadas (se ve la precisión, por ejemplo ±6 m); después toca Guardar. Si la lectura es floja (más de ±25 m) avisa que conviene repetir al aire libre.

- Este botón lee el GPS **solo cuando se toca**. (La ubicación de los técnicos en horario laboral es otra cosa, con su aviso y su horario: ver «Dónde están los técnicos».)
- Hace falta la versión del APK que trae el permiso de ubicación (2.2 o posterior). La primera vez Android pide el permiso: elegir **«Mientras se usa la app»** y dejar activada la ubicación precisa. Si el APK es anterior, el botón avisa que falta actualizar.
- En Chrome (sin APK) también funciona, con el permiso de ubicación del sitio.
- Al terminar una instalación, el técnico ya no ve la opción de «activar al cliente»: eso cambia la facturación y solo lo puede hacer quien edita clientes (antes la opción aparecía igual y fallaba, y con ella se perdía la ubicación).

## Red: cajas NAP y botellas de empalme

La pestaña **Red** (la ven los técnicos y la oficina; el administrador siempre) guarda cada **caja NAP** y cada **botella de empalme** con su ubicación:

- **Cargar una:** estando al lado, *Nueva caja NAP* o *Nueva botella de empalme* → nombre (por ejemplo NAP-12) → **«Usar mi ubicación actual (GPS)»** → Guardar. Es el mismo botón que usan las casas de los clientes. Una caja lleva cantidad de puertos (8, 16…) y, si se quiere, de qué botella de empalme sale; las dos llevan una referencia para encontrarlas (por ejemplo «poste frente a la plaza»).
- **Encontrarlas:** cada una tiene **Cómo llegar** (Google Maps / Waze). **«Ordenar por cercanía (GPS)»** pone arriba las más próximas a donde estás parado, con los metros. **«Descargar lista»** baja un CSV con las coordenadas (se puede importar en Google My Maps para verlas todas juntas).
- **Conectar a cada cliente con su caja:** en la ficha del cliente → Editar → *Caja NAP* y *Puerto*; o, **al terminar una orden de instalación**, el técnico elige la caja y anota el puerto. Las cajas se ofrecen de la más cercana a la más lejana. La app avisa si el puerto no existe o ya figura usado por otro cliente.
- **La caja dibujada:** al abrir una caja se ve como es, con la **tapa de adelante** (primera mitad: en una de 8, los puertos 1 a 4) y la **de atrás** (5 a 8), y cada puerto como un conector numerado en filas de a 4: **verde = libre**, **lleno = ocupado** (con el nombre del cliente abajo) y **amarillo = repetido**. Arriba dice «Quedan 5 puertos libres» o «Caja llena». Al **guardar una caja nueva se abre sola así**, con todos los puertos libres, lista para ir cargando.
- **Cargar y cambiar clientes en los puertos (oficina, administrador y técnicos):** tocá un **puerto libre** y elegí al cliente que está conectado ahí **sin escribir nada**: se abre con dos solapas, **«Por instalar»** (los abonados nuevos; arriba los que tienen una instalación abierta y después los más cercanos a la caja, con los metros) y **«Ya instalados»** (los que todavía no tienen caja, también de la más cercana a la más lejana; primero, si hay, los que ya figuran en esta caja pero sin puerto). La solapa «Ya instalados» **no dice cuántos clientes hay** (ni en el título ni en el aviso): muestra hasta 15 (8 al técnico) y, si no está el que buscás, se escribe su nombre. Tocás al cliente y queda cargado en ese puerto (un abonado por instalar sigue «Por instalar» hasta que se lo active). Si el cliente ya tiene lugar en otra caja o puerto no aparece en las listas, pero **escribiendo el nombre o la calle** se busca entre todos y, al elegirlo, pregunta antes de pasarlo (y el lugar anterior queda libre). Tocando un **puerto ocupado** se ve de quién es y su calle, y desde ahí **«Mover a otra caja o puerto»** o **«Sacar de esta caja»** (el puerto queda libre; el cliente sigue en el sistema). Un técnico ve en «Por instalar» solo a los abonados de sus órdenes, en «Ya instalados» hasta 8 (los más cercanos), y busca con 3 letras como mínimo viendo hasta 8 resultados, con nombre y calle (sin teléfono ni datos de facturación): no es una lista de todos los clientes.
- **Para revisar:** los clientes que no tienen puerto cargado, tienen uno que la caja no tiene o comparten puerto con otro aparecen en **Para revisar** (los repetidos se marcan en amarillo), porque en esos casos el dibujo puede mostrar libre un lugar que en realidad está usado. Para ver la caja, un técnico ve nombre y calle de **todos** los clientes conectados a ella (no el teléfono, el DNI ni los precios); la ficha completa del cliente sigue limitada a lo que su perfil permite.
- **Botellas de empalme (fibra, pelos y PON):** al cargar o editar una botella se anota **qué fibra es** (por ejemplo «Fibra de 24 pelos desde ADMIN02»), **cuántos pelos tiene** (24 por defecto) y de a **cuántos por tubo** (12 por defecto), los **PON vivos** (se pueden marcar **varios**: PON 1 = VLAN 41, PON 2 = VLAN 42… hasta PON 8 = VLAN 48) y **qué hay que hacer** (queda destacado arriba en la ficha, para quien vaya a la botella). Una botella nueva se abre sola para cargar los pelos.
- **Los pelos:** la ficha de la botella muestra cada pelo con su **color** (código de 12 colores: azul, naranja, verde, marrón, gris, blanco, rojo, negro, amarillo, violeta, rosa, celeste; los tubos también se identifican por color) y su estado: **libre**, **empalmado**, **reservado** o **dañado**. Tocando un pelo se anota **qué PON lleva**, **a qué caja o botella va** y una **nota** (por ejemplo «empalmado con el pelo 3 de la botella siguiente»). Abajo queda la lista «Qué lleva cada pelo» y **«Cajas que conecta»** (las cajas que salen de la botella más las que figuran como destino de algún pelo, con el pelo y el PON). En la ficha de la caja NAP aparece **«Llega por»**: de qué botella, pelo y PON le llega la fibra. No se puede bajar la cantidad de pelos por debajo de uno que tenga datos: primero se lo deja libre. La lista «Descargar lista» incluye la fibra, los pelos, los PON vivos y qué hay que hacer. Si el cable no usa el código de colores común, en «Pelos por tubo» se elige «No mostrar colores». Para un drop (acometida) de 1, 2 o 4 pelos sin tubos, «Pelos por tubo» tiene esa misma cantidad como opción («Drop de 1 pelo», «2 por tubo (o drop de 2 pelos)», «4 por tubo (o drop de 4 pelos)»).
- **Mover un cliente de caja o de puerto:** en la caja (tocando el puerto del cliente → *Mover a otra caja o puerto*) o en la ficha del cliente (*Caja NAP* → **Mover**). Se elige la caja de destino (las más cercanas a la casa del cliente primero) y un puerto libre; al confirmar, **el puerto de origen queda libre y el de destino ocupado en el mismo momento**, porque el puerto se guarda en el propio cliente. Lo puede hacer quien tiene el permiso de red (técnicos y oficina de fábrica). No toca la facturación. Si otra persona ocupó ese puerto mientras tanto, la app lo detecta al confirmar, no mueve a nadie y pide elegir otro. Que dos clientes no compartan puerto lo controla la app al mover o cargar, no el servidor (los clientes se guardan en varios grupos y el servidor no los cruza).
- **Qué se ve:** cada caja muestra cuántos puertos están usados, cuáles quedan libres y la lista de clientes conectados con su puerto. En *Clientes* se puede buscar por el nombre de la caja y filtrar *Sin caja NAP* para completar los que faltan. El CSV de clientes trae las columnas *caja nap* y *puerto nap*.
- **Caja iluminada o sin empalmar:** una caja NAP nueva arranca **sin empalmar** (se ve gris en el plano y en la ficha, y lleva un cartel «Sin empalmar» en la lista y en el filtro de arriba de **Red**). Cuando se termina de empalmar y ya tiene luz, en su ficha se toca **«Marcar iluminada»**: pasa a verde en el plano (y a la lista de filtros queda «Sin empalmar» para las que todavía faltan). Se puede volver a marcar como sin empalmar en cualquier momento con el mismo botón. Es un dato de esa caja física en particular, así que **no se copia** al «Clonar con todo lo que cuelga»: la copia siempre arranca sin empalmar, como una caja nueva.
- **Permisos:** el permiso nuevo **«Cargar y editar la red»** se activa por perfil en Ajustes → Usuarios (viene encendido para técnicos y oficina). Quien no lo tiene igual ve las cajas en la ficha del cliente, pero no puede cambiarlas. **Eliminar** un punto solo lo puede quien edita clientes, y el servidor no deja borrar una caja con clientes conectados (hay que pasarlos antes a otra) ni una botella de la que sale otra caja.
- Los datos entran en las copias de seguridad como cualquier otro, y la lista queda guardada en el celular para consultarla sin señal. Se necesita el APK 2.2 o posterior para el GPS (el mismo que ya se usa para las casas); **no hace falta un APK nuevo**.

## Red: splitters (divisores ópticos) para armar el plano de la FTTH

Además de la caja NAP y la botella de empalme, la pestaña **Red** tiene un tercer punto: el **Splitter**, para anotar los divisores ópticos pasivos que reparten una fibra en varias y así dejar cargado el plano completo de la red, desde la OLT hasta cada caja.

- **Cargarlo:** *Nuevo splitter* → nombre (por ejemplo SPL-01) → **relación** (1x2, 1x4, 1x8, 1x16, 1x32 o 1x64: cuántas salidas tiene) → de qué botella, splitter o caja sale (opcional, es solo el rótulo «Sale de»). No lleva puertos ni fibra propia: un splitter nuevo se abre solo con todas sus salidas libres.
- **Las salidas:** igual que los pelos de una botella, cada salida tiene su **color** (el mismo código de 12 colores) y su estado: **libre**, **conectada**, **reservada** o **dañada**. Tocando una salida se anota **a qué caja, splitter o botella va** y una nota (por ejemplo «pigtail azul» o «sigue al poste 4»); no lleva PON, porque el PON es de la fibra que entra y no cambia al dividirse.
- **El plano completo, un punto a la vez:** la fibra de la **botella** lleva (por su pelo) hasta el splitter; la salida del splitter lleva a otro splitter o a una caja NAP; y, como en el caso de Mauro, un splitter puede estar alojado **dentro de una caja NAP**, con una salida alimentando esa misma caja (la «primaria») y la otra saliendo hacia una segunda caja NAP (la «secundaria»). En cada ficha, **«Sale de»** y **«Llega por»** ahora mezclan botellas y splitters sin problema: dicen de qué punto viene (pelo o salida, con el número) y qué lleva cada uno, para poder seguir el camino de la señal paso a paso tocando los botones.
- **Para revisar:** no se puede bajar la relación de un splitter (por ejemplo de 1x4 a 1x2) si alguna de las salidas que quedarían afuera ya tiene datos cargados; primero hay que dejarlas libres. Tampoco se puede borrar un splitter del que sale otro punto de la red (caja, botella u otro splitter): hay que desconectarlo antes.
- **Buscarlos y exportarlos:** en la lista de Red hay un filtro **Splitters** (además de Cajas NAP y Botellas), que muestra la relación y cuántas salidas están en uso. El CSV de Red suma las columnas *relación splitter* y *salidas usadas*.
- **Permisos:** usa el mismo permiso **«Cargar y editar la red»** de las cajas y botellas; no hay uno nuevo. Quien no lo tiene ve la ficha del splitter (para seguir el camino de la fibra) pero no puede tocar nada. No hace falta un APK nuevo.

## Red: OLT (el origen de la fibra)

El cuarto punto de la pestaña Red es la **OLT**: el equipo de donde sale la fibra, con la cantidad de puertos GPON que tenga (por ejemplo 8), para dejar marcado el origen de toda la red.

- **Cargarla:** *Nuevo* → OLT → nombre (por ejemplo OLT-01) → **cantidad de puertos**: a diferencia del splitter (que tiene una relación fija: 1x2, 1x4…), la OLT se carga con el número de puertos que tenga el equipo, de 1 a 288. No tiene **«Sale de»**: es la raíz de la red, no sale de ningún otro punto.
- **Los puertos:** igual que las salidas de un splitter, cada puerto tiene su **color** (el mismo código de 12 colores) y su estado: **libre**, **conectado**, **reservado** o **dañado**. Tocando un puerto se anota **a qué botella, splitter o caja va** y una nota; tampoco lleva PON, porque la OLT es la que entrega la señal, no la recibe.
- **El plano completo:** de un puerto de la OLT sale, por lo general, una botella de empalme, que por su pelo lleva a un splitter y de ahí hacia las cajas, igual que ya se explica arriba. Y, como pidió Mauro: de la **botella principal** puede salir una **botella secundaria**, empalmada en la **segunda salida del primer splitter 1x2**, con su propio **splitter 1x4** para terminar de repartir lo que falta — «Sale de» y «Llega por» siguen el camino completo sin importar cuántas botellas y splitters se encadenen.
- **Para revisar:** no se puede bajar la cantidad de puertos si alguno de los que quedarían afuera ya tiene datos cargados; primero hay que dejarlo libre. Tampoco se puede borrar una OLT de la que sale otro punto de la red: hay que desconectarlo antes.
- **Buscarla y exportarla:** en la lista de Red hay un filtro **OLT** (junto a Cajas NAP, Botellas y Splitters), que muestra la cantidad de puertos y cuántos están en uso. El CSV de Red suma las columnas correspondientes.
- **Permisos:** usa el mismo permiso **«Cargar y editar la red»**; no hay uno nuevo. Quien no lo tiene ve la ficha de la OLT pero no puede tocar nada. No hace falta un APK nuevo.

## Red: el plano de la red (el dibujo de las conexiones)

Con la OLT, las botellas, los splitters y las cajas ya cargados, la pestaña Red tiene un botón **«Ver plano de la red»** que arma solo, con lo que ya está cargado, un dibujo de todo el recorrido de la fibra: de la OLT hacia abajo, cada botella, cada splitter y cada caja en su lugar, conectados con el mismo color de 12 colores que ya se usa en las salidas y los pelos.

- **Para qué sirve:** es una forma rápida de revisar que el diseño está bien armado, sin tener que entrar punto por punto. Una línea **punteada** (sin color) avisa que una caja, botella o splitter está declarado como «Sale de» pero todavía no se anotó por cuál pelo, salida o puerto sale exactamente: falta cargar ese dato en el punto de origen.
- **Se arma solo:** no hay nada que dibujar a mano. Cada vez que se abre el plano, se arma de nuevo con los datos más recientes; para verlo actualizado después de cargar algo nuevo (por ejemplo, un splitter con sus dos niveles y una botella secundaria saliendo de la segunda salida), basta con volver a abrirlo o tocar **«Actualizar»**.
- **Varios orígenes:** si hay más de una OLT, o quedó alguna botella vieja sin OLT cargada (de antes de que existiera este punto), cada una se dibuja como su propio árbol, uno al lado del otro.
- **Recuadro por PON:** cuando una botella tiene marcado en su ficha qué PON lleva («PON vivos»), toda su rama (sus splitters y sus cajas) se dibuja adentro de un recuadro punteado de color, con una etiqueta («PON 1», o «PON 1 + PON 3» si la misma fibra lleva más de uno). Con varios PON uno al lado del otro en el mismo plano, sirve para ubicarse de un vistazo sin tener que seguir cada línea; una botella sin ningún PON marcado todavía no lleva recuadro.
- **Tocar una caja** del plano abre su ficha, igual que en la lista. **Acercar / Alejar / Tamaño real** cambian el zoom para ver mejor un sector o toda la red junta.
- **Imprimir:** el botón **«Imprimir»** arma una hoja aparte (A4 apaisada, para que entre un árbol más ancho que alto) solo con el dibujo, lista para guardar en papel o como PDF. Desde la aplicación del celular abre la impresión de Android; desde la computadora, abre el diálogo de impresión del navegador.
- **Permisos:** hay dos permisos aparte, para que cada administrador elija qué ve cada técnico (además del permiso de red, que es el que da acceso a la pestaña):
  - **«Ver el plano de la red»**: el dibujo completo, con la OLT, las botellas, los splitters y las cajas, como se describió arriba.
  - **«Ver las cajas NAP»**: una versión simplificada (el botón dice «Ver cajas NAP» y el dibujo «Cajas NAP»), con nomás las cajas NAP (nombre, referencia y puertos) una al lado de la otra, sin mostrar los splitters ni la OLT. Sirve para técnicos que solo necesitan saber qué cajas hay y dónde, sin ver cómo está armada la red por dentro. Si el técnico tiene los dos permisos, ve el plano completo.
  
  Los dos vienen **apagados** por defecto en los técnicos (se activan por usuario en Ajustes → Usuarios, igual que los demás permisos); «Ver el plano de la red» viene **encendido** en la oficina. Desde cualquiera de las dos vistas no se puede editar nada: solo mirar y, si se toca una caja, ver su ficha con los mismos permisos de siempre.

## Red: clonar con todo lo que cuelga

Una red FTTH suele repetir el mismo esquema una y otra vez: por ejemplo, cada puerto PON de una OLT reparte con la misma cascada de splitters hasta terminar en el mismo número de cajas. Cargar esa cascada a mano, puerto por puerto, es lo que más tiempo lleva. Para eso, en la ficha de cualquier botella, splitter o caja hay un botón **«Clonar con todo lo que cuelga»** que arma de nuevo, en un solo paso, toda la rama que sale de ese punto.

- **Qué copia:** el punto tocado y todo lo que cuelga de él (según lo que ya muestra «De acá salen», así que nunca copia de más ni de menos), con el mismo tipo de cada punto, la cantidad de puertos o la relación de cada splitter, la cantidad de pelos de cada botella, y qué pelo o salida de cada punto lleva a cuál copia (con el mismo estado: conectado, reservado, etc.). Una rama con una conexión declarada pero sin el pelo o la salida anotada (la línea punteada del plano) se copia igual de incompleta: hay que terminar de anotarla en la copia, como en el original.
- **Qué no copia:** la ubicación (GPS), la referencia para encontrarlo, las notas, la fibra, los PON vivos y «qué hay que hacer» del original. Son datos de ese punto físico en particular: la copia es otra caja, otro splitter, en otro lugar, así que hay que cargarlos de nuevo (o dejarlos vacíos hasta que se instale).
- **Cómo se usa:** se elige de dónde sale la copia (una OLT, una botella o un splitter que ya exista; no puede ser el propio punto ni algo que cuelgue de él) y cómo se van a armar los nombres de la copia, con al menos una de estas dos opciones (se pueden combinar):
  - **Prefijo** (por ejemplo «PON 2»): se agrega adelante del nombre de cada punto copiado.
  - **Buscar / Reemplazar** (por ejemplo buscar «pon 41» y reemplazar por «pon 42»): cambia ese texto en el nombre de cada punto copiado que lo tenga. Sirve para repetir un esquema que ya tiene el número de PON metido en cada nombre («Splitter 1/4 pon 41», «Caja 1/4 pon 41 Primaria»…) sin terminar con un prefijo pegado adelante.

  Cualquiera de las dos formas sirve para no repetir nombres; si el resultado coincide con un punto que ya existe, avisa cuál y no crea nada. Antes de crear algo, avisa cuántos puntos va a copiar, para confirmar.
- **Después de clonar**, la copia queda colgada del punto elegido pero sin el pelo o la salida anotados ahí todavía (se ve con línea punteada en el plano): falta el último paso, igual que con cualquier punto nuevo, de ir a la ficha de ese padre y anotar por cuál pelo o salida sale exactamente.
- No agrega ningún permiso nuevo: usa el mismo permiso de «Cargar y editar la red» que ya hace falta para crear o editar cualquier punto. La OLT no se puede clonar (no tiene sentido duplicarla).

## Instalaciones por día, semana y mes

Pestaña **Instalaciones** (la ven el administrador y la oficina; el técnico no, porque no ve las órdenes de todos). Arriba se elige **Día**, **Semana** (de lunes a domingo) o **Mes**; con `‹` y `›` se va al período anterior o siguiente, «Volver a hoy» regresa, y el gráfico de barras (14 días, 8 semanas o 12 meses) se toca para saltar a cualquier período. Abajo muestra:

- **Instaladas**, las del **período anterior** (con la diferencia en una frase) y las que quedaron **sin hacer** (órdenes de instalación programadas en ese período que siguen abiertas).
- **Por técnico**: cuántas hizo cada uno (y «Sin técnico» si no había uno asignado).
- La **lista de clientes** instalados, con la hora; con un renglón por día en semana y mes. Tocar un renglón abre la ficha del cliente. Las que se cerraron sin cobrar llevan «Sin cobrar» (y un aviso arriba) hasta que se cobran.

Una instalación cuenta **el día en que se cerró su orden** (no el día para el que estaba programada). Si un cliente pagó la instalación pero no tiene ninguna orden de instalación cerrada (la cargó la oficina a mano), también cuenta, el día de su primer cobro, y se marca «Sin orden». Las órdenes canceladas y las abiertas no cuentan. En el **Resumen** hay un recuadro «Instalaciones en <mes> · hoy N» que lleva a esta pestaña.

## Órdenes canceladas: quién, cuándo y cómo reabrirlas

Una orden solo se cancela a mano: el administrador o la oficina tocan **Cancelar orden** y confirman (el sistema nunca cancela solo). Queda anotado **quién** la canceló y **cuándo**, y se ve en la propia orden («Cancelada el 06/11/2026 01:52 por Laura») y en la ficha del cliente, debajo de la fecha programada. Las que se cancelaron antes de esta versión muestran la fecha y la hora, pero no el nombre.

Si fue un error, en **Órdenes → Cerradas** (o «Todas») la orden cancelada tiene **Reabrir la orden**: vuelve a quedar pendiente, con el mismo técnico, sin la marca de cancelada. El técnico ve que se canceló, pero no puede cancelar ni reabrir. Cancelar una orden no cambia el estado del cliente (sigue «Por instalar» hasta que se lo active).

## Cobros del técnico y cierre de caja por cobrador

Si un técnico cobra la instalación, una reinstalación (mudanza) o un reclamo, lo carga en la app y entra a la caja del día con su nombre:

- **Darle el permiso:** Ajustes → Usuarios → editar al técnico → *Cobrar instalaciones y reclamos en la calle*. Viene apagado: lo prendés solo a quien cobra. Con ese permiso **no cobra mensualidades** (eso sigue siendo de la oficina) y **no ve la caja ni lo que cobran otros**.
- **Cómo lo carga el técnico:** (1) pestaña **Mis cobros** → busca al cliente → *Cobrar* (instalación, reinstalación, reclamo u otro, con el medio de pago; la instalación y la reinstalación llevan el precio fijo); (2) desde la ficha del cliente → *Cobrar instalación o reclamo*; (3) **al terminar una orden**, tildando *Cobré este trabajo* (el concepto se completa según el tipo de orden). Siempre se registra con la fecha de hoy y a su nombre: no puede poner otra fecha ni borrarlo. Si se equivoca, la oficina anula el recibo y se carga de nuevo.
- **Precios fijos de instalación y reinstalación:** los carga **solo el administrador** en *Ajustes → Precios de instalación* (hoy **instalación $ 65.000** y **reinstalación $ 35.000**, que es la mitad redondeada). El técnico ve el monto ya puesto y **no lo puede cambiar**; el servidor además rechaza cualquier otro importe y le dice cuál es el vigente. Si cambiás un precio, le llega al técnico solo, sin que reinstale nada. La oficina ve el precio de lista ya completado, pero puede ajustarlo (descuento, pago en cuotas). «Reclamo o visita técnica» y «Otro» siguen con monto libre.
- **La reconexión solo se cobra si el cliente tiene deuda, y la cobra la oficina:** el técnico **nunca** la cobra (el servidor se lo rechaza; además no ve la deuda del cliente). En la oficina, «Reconexión» aparece en *Cobrar* —y al terminar una orden de *Reconexión* se ofrece «Cobré este trabajo»— **solo si el cliente tiene deuda anterior pendiente o meses vencidos**; si está al día no se ofrece. El monto es libre (no hay precio fijo). Ojo con el orden: se carga la reconexión **antes** que el pago de la deuda, porque cuando la deuda queda en cero ya no se puede cobrar. Los recibos viejos que dicen «Reconexión» se siguen viendo igual.
- **Mis cobros:** muestra lo que cobró hoy y los últimos 7 días, y cuánto efectivo tiene que entregar hoy.
- **Instalación una sola vez por cliente; reinstalación para una mudanza:** lo que decide el concepto es **lo cobrado**, no el estado del cliente (la oficina carga al abonado nuevo como «activo» y el técnico ni ve ese estado; antes eso hacía que al técnico solo le saliera «Reinstalación»). A quien cobra en la calle se le ofrece **«Instalación»** ($ 65.000, precio fijo) si el cliente está «Por instalar» o tiene una **orden de instalación abierta** y todavía no se le cobró la instalación; la orden de instalación la propone por defecto. **«Reinstalación (mudanza)»** se ofrece a todo cliente salvo a uno «Por instalar». Cuando a un cliente ya se le cobró la instalación (sin anular el recibo) y vuelve a tener una orden de instalación, el cierre propone Reinstalación. El servidor lo controla igual aunque el técnico no vea los pagos: rechaza una segunda «Instalación» al mismo cliente y le dice la fecha en que ya se cobró y que cobre la reinstalación (si el recibo se anuló, se puede volver a cobrar). La oficina (que cobra de todo) no tiene esta restricción.
- **Cerrar una instalación sin cobrar (el cliente paga en la oficina):** al terminar una orden de **instalación** de un cliente al que todavía no se le cobró la instalación (y con un perfil que puede cobrar), si no se marca «Cobré este trabajo» hay que **elegir el motivo** (*El cliente va a pagar en la oficina*, *va a pagar otro día* u *Otro motivo*, que pide contar qué pasó). La orden se cierra igual y guarda `sinCobro` y `sinCobroNota` (no hay validación nueva en el servidor: las órdenes aceptan esos campos como cualquier otro). Mientras no se registre un pago de instalación de ese cliente, la tarjeta de la orden cerrada muestra «**Sin cobrar**» con el motivo y, **a quien puede cobrar (oficina y administrador)**, el botón **«Cobrar la instalación»** (abre el cobro con «Instalación» elegida) y, arriba de la lista de órdenes, un aviso con las instalaciones sin cobrar. Todo se calcula con lo cobrado: apenas se cobra la instalación, desaparece solo (queda «La instalación se cobró después de cerrar la orden»). **No es una deuda**: la instalación no entra en lo que se le factura por mes. Además, una orden «Pendiente» o «En camino» ofrece **«Ya la terminé»** (abre el cierre sin pasar por «Llegué, empiezo») y, si no tenía técnico, queda a nombre de quien la cierra. Prueba: `tests/e2e_sincobro.py`.
- **Cobro repartido entre 2 medios de pago (50.000 por transferencia + 15.000 en efectivo):** al cerrar una orden («Cobré este trabajo»), en «Cobrar» y también para la oficina aparece **«Cobrar con 2 medios de pago»**. Se eligen los dos medios y se escribe el monto de uno: **el otro se completa solo** hasta el precio fijo (el técnico no puede cambiar el total; la oficina escribe los dos montos y puede cobrar otro importe). No se ofrece en mensualidad ni deuda anterior (para eso está «Pagar deuda»). Queda **un solo recibo con un registro por medio** (igual que «Pagar deuda»), un único aviso por WhatsApp y el recibo lista cada medio; si uno es transferencia, el técnico adjunta la foto del comprobante y **la foto queda solo en el registro de la transferencia**. El servidor lo controla (`guard()`, cobros en la calle de instalación y reinstalación, agrupados por cliente y concepto dentro del mismo lote): los montos **tienen que sumar exactamente el precio fijo**, no se repite el medio, todos van con el mismo recibo, cada parte lleva al menos un centavo y no puede haber dos cobros del mismo concepto al mismo cliente en un lote (antes dos registros de $ 65.000 en un mismo envío no los frenaba nadie). Es todo o nada: si algo no cierra no se registra ninguna parte. El servidor admite hasta un registro por cada medio (4), la pantalla ofrece 2. Pruebas: `tests/test_server.js` («varios medios») y `tests/e2e_variosmedios.py`.
- **El técnico no ve pagos:** no hay caja, ni cobranzas, ni morosos, ni lo que se le cobró a un cliente: el servidor ni siquiera le manda los pagos. Lo único que ve es **Mis cobros**: los recibos que cargó él mismo (hoy y los últimos 7 días) y cuánto efectivo debe entregar. Cuando el administrador mira la app «como técnico» (*Vista: …*), esa pestaña también muestra solo los cobros de ese técnico.
- **El técnico no ve si el cliente está activo o suspendido por falta de pago:** el servidor no le manda el estado «Activo» ni «Suspendido» (ni la fecha de corte, la reconexión ni las promesas de pago), así que no aparece en la lista, en la ficha, en el mapa de la caja NAP ni en el buscador, y tampoco están los filtros *Activos* y *Suspendidos*. Sí ve **«Por instalar»** y **«Baja»**, porque con eso trabaja. Lo que guarda el técnico (por ejemplo la ubicación) no pisa el estado real del cliente. La oficina y el administrador lo ven todo como antes.
- **El técnico no ve los servicios adicionales del cliente (Multimedia, Multimedia Net):** son de facturación, así que el servidor no se los manda (lo mismo que el precio). No aparecen en la lista, en la ficha, en el cobro ni como filtro. Los ve quien factura: administrador, oficina o quien tenga cobrar, caja, editar clientes o precios. Lo que guarda el técnico no los borra, y no puede cambiarlos.
- **Transferencias: el técnico adjunta la foto del comprobante.** Si el técnico cobra por **transferencia** (en *Cobrar*, en *Mis cobros* o al terminar una orden), aparece **«Comprobante de la transferencia»** y tiene que adjuntar la foto del comprobante con uno de dos botones: **«Sacar foto con la cámara»** (abre la cámara del celular directo, sin pasar por el selector de archivos) o **«Elegir una foto»** (la captura que le mandó el cliente, o una foto que ya tenga). Los dos botones están igual en *Cobrar*, en *Mis cobros* y al terminar una orden de instalación o reclamo. Sin la foto no se cierra la orden ni se registra el cobro. La foto se achica en el celular (menos de 400 KB) y se sube apenas la elige, y se ve en miniatura. El servidor también lo exige (no alcanza con esquivar la pantalla): rechaza una transferencia sin foto, un medio de pago inventado y una foto que ya se usó en otro cobro. Cada foto sirve para un solo cobro y queda atada a él: no se puede cambiar después. Las fotos que se suben y no se usan se borran a los 2 días. Con **efectivo** no se pide nada. La oficina (que cobra de todo) no tiene la obligación. **Hace falta el APK nuevo para que «Sacar foto con la cámara» abra la cámara directo** (con el APK anterior, o en el navegador de un celular, el botón abre igual el selector de fotos de Android, que también ofrece la cámara). El APK no pide permiso de cámara: la foto se guarda en un archivo temporal de la app (no en la galería) y se borra al sacar la siguiente.
- **Ver el comprobante:** en la caja del día, el cobro lleva el aviso **«Con comprobante»**, y en el **recibo** aparece **«Ver comprobante de la transferencia»** para el administrador, la oficina (los que ven los cobros) y el técnico que lo cobró. No es un enlace público: la foto se pide con la sesión. Las fotos no entran en las copias de seguridad diarias (solo los datos), así que quedan en el servidor aparte.
- **Mercado Pago y «Otro» no piden foto** (hoy solo la transferencia). Si querés que también la pidan, se cambia en una línea.
- **Cierre de caja:** en Cobranzas → *Caja del día* hay una tabla **Por cobrador** (recibos, efectivo, otros medios y total de cada persona, incluida la oficina) y cada cobro dice quién lo hizo. El efectivo de cada persona es lo que tiene que entregar. Los cobros anulados no suman.
- Los cobros anteriores a esta versión no tienen nombre de cobrador y figuran como «Sin dato». **No hace falta un APK nuevo.**

## Routers MikroTik: traer los clientes (solo lectura)

El sistema **no se conecta a tus routers ni guarda usuario o clave de ninguno**. Es al revés: cada router corre un script de **solo lectura** que le manda al sistema la lista de lo que tiene cargado. Por eso el sistema no puede cortar ni cambiar nada en un router, aunque alguien robe una cuenta de la app. No hay que abrir puertos ni exponer el router a internet (solo necesita salir por HTTPS).

- **Alta:** Ajustes → *Routers MikroTik* → *Agregar router*. Poné el nombre (ADMIN02, FM04…) y marcá qué clientes tiene: **IP fija** (lee las colas simples), **DHCP** (leases estáticos) y/o **PPPoE** (secretos y perfiles; *nunca* lee ni envía contraseñas). Te muestra el script con el acceso de ese router.
- **En el router:** WinBox → Nuevo terminal. (1) pegá la prueba de conexión, (2) pegá el script, (3) ejecutalo una vez con `/system script run yapur-clientes` (con miles de clientes tarda unos minutos), (4) si funcionó, pegá la programación para que lo mande solo todos los días a las 03:30. El script es de permisos `read,test`: no puede escribir en el router.
- **Clientes detectados:** en el router → *Clientes detectados*. Junta colas, PPPoE y DHCP en una fila por cliente (por IP), reconoce a los que ya cargaste (por IP, usuario PPPoE o nombre) y asigna el plan por velocidad. *Importar* crea los nuevos con IP, usuario PPPoE, MAC y el nombre del router; lo deshabilitado entra como suspendido. Teléfono, dirección y DNI se completan después. No pisa clientes que ya están.
- **Completar la IP de clientes que ya tenés cargados (con archivos .rsc):** Ajustes → *Routers MikroTik* → **Completar IP con archivos .rsc**. Elegís los exports de los routers (en WinBox: `/export file=admin`, y bajás el `.rsc` desde *Files*; sirven los 4 juntos). Los archivos **se leen en tu equipo: no se suben ni se guardan, y las contraseñas y claves que traen no se leen** (solo se toman nombre, IP, MAC y velocidad de las colas, DHCP y PPPoE). Solo se completa la IP de los clientes que **no la tienen** (los de baja y los que ya tienen IP no se tocan) y no se cambia nada en los routers. Los emparejá por nombre, sin importar tildes, mayúsculas ni el orden («Ana Muñoz» = «Muñoz Ana-12»; el sufijo «-104» y el número del comentario se ignoran), o por usuario PPPoE:
  - **Seguros** (mismo nombre o usuario, una sola IP) y **Parecidos** (el nombre de uno está dentro del otro, por ejemplo «Figueredo Emiliano Ricardo» y «Emiliano Figueredo», una sola IP) vienen **marcados**; en cada fila ves el nombre que tiene el router para comprobar que es la misma persona.
  - **A revisar** (no vienen marcados): hay varias IP posibles (elegís cuál; al elegirla se marca), el nombre tiene un error de tipeo (Caseres / Caceres) o **dos clientes reclaman la misma IP**. Nunca deja guardar la misma IP en dos clientes.
  - **Sin coincidencia:** no aparecen en los archivos (o la IP que les tocaría ya es de otro cliente): se cargan a mano.
  - Con *Guardar* se escribe **solo la IP**; el resto de la ficha queda igual. Se puede repetir las veces que haga falta: lo ya guardado no se vuelve a ofrecer.
  - Con una lista parecida a la de octubre (735 clientes) y los 4 exports del 31/10/2026: 428 seguros, 112 parecidos, 92 a revisar y 103 sin coincidencia.
- **Qué no toma como cliente:** colas con rangos o varias IP, colas repetidas con la misma IP y usuarios PPP que no son PPPoE (VPN).
- **Seguridad:** el acceso de cada router solo sirve para *dejar* la lista (no para leer nada del sistema). Si lo perdés o lo querés cambiar, *Script* genera uno nuevo y el anterior deja de valer (hay que volver a pegar el script en ese router). Un router borrado deja de poder enviar.
- **Para saber:** la lista de cada router no entra en las copias de seguridad (se vuelve a armar sola con el próximo envío).
- **Sin probar en un router real:** el script se armó con la sintaxis de RouterOS 6.4x/7.x pero **no se pudo correr en un MikroTik desde acá**. Probalo primero en uno chico (por ejemplo un nodo con IP fija). Si el router responde «not enough permissions», agregá el permiso `write` al script y a la programación (el script igual no escribe). El paso «Si algo falla» del mismo cuadro explica los demás casos.
- Más adelante, cortar y reconectar desde el sistema se podría agregar como un script aparte que el router *consulta* (siempre del lado del router, sin dar acceso al sistema); hoy no existe.

## Dar de baja a un cliente (y que no desaparezca hasta retirar los equipos)

- **Cómo:** abrí la ficha del cliente → **Dar de baja** (lo ve quien puede editar clientes). Elegís la fecha, un motivo si querés, y si **tiene equipos en comodato para retirar** (viene tildado). Si lo dejás tildado también se crea la orden de **Retiro de equipo**, sin asignar, para que la tome un técnico.
- **Qué pasa mientras falta retirar:** el cliente queda de baja (no se factura ni aparece para cobrar) pero **sigue en la lista de «Todos»** con el aviso **«Baja · retirar equipo»**, y también en el filtro **«Equipos por retirar»** (que ven también los técnicos). La ficha dice desde cuándo está de baja y el motivo.
- **Confirmar el retiro:** en la ficha, **Confirmar equipos retirados**; o cuando el técnico cierra la orden de «Retiro de equipo», la pantalla de cierre ofrece «Confirmar que se retiraron los equipos» (tildado). Recién ahí sale de «Todos».
- **Después:** el cliente no se borra nunca. Se encuentra en el filtro **«Bajas»** (con buscador) con su historial, pagos y fechas de baja y de retiro. Para reactivarlo: Editar → Estado.
- **Baja sin equipos:** destildá «Tiene equipos en comodato» y sale de la lista en el acto.
- **Ojo con la deuda:** al pasar a baja deja de figurar como deuda del mes; el formulario avisa si debe algo. La «Deuda anterior» sí se mantiene.

## Nodo o torre: se elige de una lista

En la ficha del cliente («Editar cliente» o «Cargar datos del abonado») y en **Terminar orden** de una instalación, **Nodo o torre** es una **lista** con los nodos que ya figuran en algún cliente (si un nodo está escrito de dos maneras, por ejemplo «ADMIN02» y «admin02», aparece una sola vez), más **Sin definir** y **Otro (escribirlo)…** para uno que todavía no existe: al elegir «Otro» aparece el campo para escribirlo y desde ahí queda en la lista para los demás. El nodo se usa también para elegir qué router hace la prueba de conexión (ping).

## Que los técnicos no vean el plan contratado

- **Qué cambia:** el técnico ya no ve el plan de ningún cliente: ni el chip del plan en la lista (ni «Sin plan»), ni la fila «Plan» de la ficha, ni el botón «Copiar cola de MikroTik», ni la lista de planes. Sigue viendo lo que usa para trabajar: domicilio, teléfono, IP, usuario, nodo, caja NAP y equipo.
- **No es solo esconderlo en pantalla:** el servidor no le manda el plan del cliente (ni los planes anteriores del historial) ni los planes en sí; aunque alguien abra las herramientas del navegador no los encuentra. Al guardar sus datos técnicos no borra el plan del cliente.
- **Quién lo ve:** administrador y oficina. Para dárselo a un técnico en particular (o a un perfil), Ajustes → permiso **«Ver el plan contratado de cada cliente»**; la persona lo recibe en el acto, sin salir de la app. El permiso **«Ver planes y precios»** sigue siendo aparte: es el de los importes.
- **Excepción: elegir el plan de un abonado nuevo.** Al instalar, el técnico tiene que poder anotar qué plan quiere el cliente. Para eso existe el permiso **«Elegir el plan de un abonado por instalar»** (viene **prendido** en técnicos y oficina; se apaga por perfil en Ajustes, igual que los demás). Con él, el técnico recibe la **lista de planes con nombre y velocidad, sin precios ni historial**, y ve el plan **solo de los clientes «por instalar»**; el de los clientes ya instalados, su precio y sus servicios siguen ocultos (el servidor tampoco se los manda). Puede elegir o quitar el plan de un abonado por instalar y **nada más** de la facturación: el servidor rechaza cualquier otro cambio (precio, servicios, ciclo, desde cuándo se cobra, deuda) y rechaza cambiar el plan apenas la oficina activa al cliente. Con el permiso apagado todo queda como antes: sin planes y sin poder elegirlo. El botón «Copiar cola de MikroTik» sigue siendo solo de quien tiene «Ver el plan contratado de cada cliente».
- «Ver como…» un técnico muestra lo mismo que ve él.
- **Tampoco ve cuántos clientes tiene la empresa:** en la lista de clientes el técnico no ve el total (ni «Ver más (593)»); solo cuenta resultados cuando una búsqueda trae 20 o menos. Oficina y administrador ven el total como siempre. (La app le baja la lista completa para poder buscar sin conexión; si no querés que un técnico tenga la lista entera, sacale «Ver todos los clientes» en Ajustes y verá solo los de sus órdenes.)

## El técnico completa a un abonado nuevo (nombre, teléfono, domicilio, DNI, caja y puerto)

- **Dónde:** en la tarjeta de la orden hay un botón **«Cargar datos del abonado»** (en una instalación o un abonado por instalar; en otros casos dice «Datos del abonado»). Está aparte de **«Editar orden»**, que cambia la orden (tipo, fecha, qué hay que hacer) y no al abonado. En la ficha del cliente el botón de edición también dice «Cargar datos del abonado».
- **Qué puede cargar el técnico en un abonado nuevo:** nombre, teléfonos (si su perfil ve teléfonos), calle, localidad, **DNI**, referencia, ubicación, el **plan que quiere el cliente** (una lista con nombre y velocidad, sin precios; la oficina lo revisa antes de activar el servicio) y los datos técnicos: tecnología, usuario, IP, **nodo o torre**, equipo y la **caja NAP con su puerto**. El DNI se guarda pero ese perfil no lo vuelve a ver (si ya está cargado, se deja vacío y no se borra).
- **Cuándo:** solo con un abonado **por instalar** o con una **orden de instalación abierta** (la de él o una sin asignar). En clientes ya instalados, el técnico sigue editando únicamente los datos técnicos. El precio, el estado, el ciclo y la deuda siguen siendo solo de la oficina; el plan lo puede indicar el técnico únicamente mientras el abonado está «por instalar».
- **Terminar la orden:** el botón **Terminar** carga qué se hizo, la caja y el puerto (vienen puestos si ya se cargaron), el **plan** que eligió el cliente y el **nodo** (en una instalación) y, **si el perfil tiene «Cobrar instalaciones y reclamos en la calle»**, el cobro de la instalación con el precio fijo. Si el perfil **no** tiene ese permiso no aparece el cobro y la pantalla le dice que avise a la oficina cuánto cobró. Para dárselo: **Ajustes → Usuarios y accesos →** el técnico **→ «Qué puede hacer» → «Cobrar instalaciones y reclamos en la calle»**. Desde **«Editar orden»** también hay un acceso a **«Ir a terminar la orden»**.

## Equipos en comodato y contrato firmado en el celular

- **Cargar los equipos (técnico, oficina, administrador):** ficha del cliente → **Equipos en comodato** → *Cargar equipos*. Por cada uno: tipo (ONU, router, antena…), marca y modelo, **N° de serie o MAC**, cantidad, estado (nuevo/usado) y observaciones. Ese detalle es lo que se escribe en el contrato.
- **Hacer firmar:** en la misma ficha, **Hacer firmar el contrato**. Se confirman los datos del titular (nombre, **DNI o CUIT** y domicilio), se muestra el contrato armado con los equipos, el cliente lo lee, tilda «leí el contrato y estoy de acuerdo» y **firma con el dedo en la pantalla del celular**. Hay que escribir también la aclaración (nombre de quien firma). No deja firmar con un garabato suelto.
- **Cómo se guarda:** en el servidor, en una tabla propia que **nadie puede editar**: el texto exacto que firmó, la imagen de la firma, fecha y hora, quién tomó la firma, desde qué IP y equipo, y un **código de verificación (SHA-256)** del contenido. En la pantalla del contrato, **Verificar integridad** recalcula el código y confirma que nada se tocó. Los contratos entran en la **copia de seguridad completa** y en las copias automáticas.
- **Quién ve qué:** el técnico ve los equipos y el contrato que firmó, **sin el DNI** (sale tapado salvo que tenga el permiso de ver DNI), y no puede borrar ni aprobar nada. Oficina y administrador ven todo el registro. Permisos en Ajustes: **«Cargar los equipos en comodato y hacer firmar el contrato»** (técnicos: sí) y **«Revisar, aprobar y borrar contratos de comodato»** (técnicos: no).
- **Borrar:** solo oficina y administrador (o quien tenga ese permiso), pidiendo un motivo. **Nunca se borra de verdad**: pasa a la **papelera** (Clientes → *Contratos de comodato* → Papelera) y se puede **restaurar**. Cada paso queda anotado en el registro del contrato (quién y cuándo).
- **Cambio de titularidad:** en la ficha, **Cambio de titularidad**. Primero **firma la persona nueva**, y ese contrato queda **«en revisión»**: el anterior **sigue vigente** hasta que la oficina o el administrador lo revisa (le llega el aviso «Hay N contratos esperando tu revisión», y el filtro **«Contrato en revisión»**). Al **aprobar**, el nuevo pasa a ser el vigente y el anterior se **archiva** (queda guardado); también se ofrece actualizar el nombre, DNI y teléfono de la ficha. Si se **rechaza**, queda el anterior y el rechazado se conserva con el motivo.
- **Si cambian los equipos:** la ficha avisa «los equipos cambiaron desde que se firmó el contrato» y ofrece **Firmar cambio de equipos** (también pasa por revisión).
- **Para encontrar a los que faltan:** en la lista de clientes, el filtro **«Sin contrato firmado»**; cada cliente muestra una etiqueta con el estado de su contrato.
- **El texto del contrato** se edita en **Ajustes → Contrato de comodato** (solo administrador): se escribe o pega el texto y se tocan los datos que se completan solos (`{{titular}}`, `{{dni}}`, `{{equipos}}`, `{{fecha}}`…), más los datos de la empresa (razón social, CUIT, domicilio, representante). **El texto de arranque ya viene como definitivo** (los técnicos pueden hacer firmar desde el primer día). Si el administrador guarda un texto que diga «BORRADOR» o tenga partes «[COMPLETAR…]» no se puede marcar como definitivo, y sin eso **los técnicos no pueden hacer firmar**. Cada contrato firmado guarda su propia copia del texto, así que cambiar el texto después no altera los ya firmados.
- **El texto que viene de arranque** es el de los contratos en papel de fibra y de antena, **unidos en uno solo** (ya no hay dos): el equipo del comodato sale de la lista que se carga en la ficha de cada cliente (`{{equipos}}`) y la modalidad de `{{tecnologia}}` (*Fibra óptica «INTERNET CABLEADO»* o *Antena inalámbrica «INTERNET POR ANTENA»*), que sale de la tecnología de la ficha o, si no la tiene, de los equipos (ONU: fibra · antena: wireless). Cambios respecto del papel: cláusula **VI «Ingreso al domicilio, instalación y retiro de los equipos»** (instalar, inspeccionar, mantener, reparar, cambiar, **desinstalar y retirar**; techo, azotea y paredes; autorización del propietario) y **devolución de los equipos** a los 10 días de la baja (con valor de reposición) en la cláusula VII; se sacó el «período mínimo contratado» (contradecía la rescisión sin cargos), se arregló la remisión de la cláusula de mudanza y **la baja** (cláusula III: el cliente la pide **sin preaviso ni mes adelantado**, en persona, por teléfono o por WhatsApp, verificando su identidad, y recibe **constancia con número de referencia**; vale desde el día del pedido y se pagan los días usados; ya no hace falta «hacerse presente» ni existe el corte del día 11; no se condiciona al pago de deudas, que se siguen debiendo; YAPUR.NET puede rescindir sin causa con un mes de aviso y por falta de pago a los 30 días **con notificación previa**) y la cita de la Ley 24.240 (se dejan a salvo los derechos del consumidor); se agregó el cambio de titularidad, el aviso por WhatsApp y la jurisdicción. Viene como **definitivo**, sin CUIT (el papel no lo llevaba; si se quiere, se agrega `{{empresa_cuit}}` al texto y se carga el CUIT en Ajustes: ahí sí se exige para marcarlo definitivo). La razón social, el domicilio y el representante vienen de los contratos en papel. Si ya había guardado otro texto, en el editor aparece **«Cargar el texto sugerido (fibra y antena)»** (se toca dos veces, deja marcado «definitivo» y no se guarda hasta tocar «Guardar»).
- **Equipos de arranque en la ficha:** al cargar los equipos de un cliente que no tiene ninguno, la lista viene armada según su tecnología: **antena** → *CPE Ubiquiti LiteBeam Gen2* + *Inyector de corriente PoE* (siempre es el mismo modelo); **fibra** → una *ONU* en blanco (cambia de un cliente a otro) + su fuente. Se puede cambiar o quitar cualquier fila.
- **Importante:** es una **firma electrónica simple** (firma dibujada + registro + código de verificación), no la «firma digital» con certificado de la Ley 25.506. Sirve como constancia firmada y ordenada, pero conviene que **un abogado revise el texto final** del contrato antes de usarlo con clientes.

## Pagar deuda: escribir cuánto paga y repartirlo entre varios medios

- **Dónde:** en la ficha del cliente, el botón **Pagar deuda** (aparece cuando debe algo; lo ven oficina y administrador). También hay un acceso directo adentro de **Cobrar**.
- **Botón «Pagar todo»:** cuando hay un mes en curso para sumar, la pantalla ofrece **Pagar todo (monto)** y **Solo la deuda (monto)**. Desde **Cobrar** el acceso directo dice «Pagar todo o la deuda».
- **Cómo:** arriba muestra lo que debe (deuda anterior, cada mes y el total). Escribís **cuánto paga** y el medio (efectivo, transferencia, Mercado Pago u otro). Si lo reparte, tocás **Agregar otro medio de pago**: por ejemplo 15.000 en efectivo y la transferencia se completa sola con los 4.000 que faltan. **Registrar pago** y listo.
- **Qué cuenta como deuda:** la «Deuda anterior» y los meses que ya vencieron. El mes en curso que todavía no vence («Mes a vencer») **no es deuda**: se aclara abajo del total. Si el cliente también lo paga, tocás **Pagar todo (monto)**: pone deuda + mes en curso de una vez (después se puede repartir entre medios). **Solo la deuda** vuelve al total vencido. Si un cliente no figura con deuda, no aparece el botón: su deuda de meses viejos tiene que estar cargada en la ficha (Editar → «Deuda anterior que falta cobrar»).
- **A qué se aplica:** a lo más viejo primero. Antes de registrar, la pantalla muestra «Así queda registrado» con cuánto va a cada mes y con qué medio.
- **Un solo recibo:** sale un recibo con **«Contado + Transferencia»** y cada renglón dice con qué medio se pagó. En «Cobrado hoy» aparece una sola fila con el total y los medios; la **Caja del día** suma cada medio por separado.
- **Pagos parciales:** si escribe menos de lo que debe, el resto queda como deuda (la pantalla avisa cuánto). No deja escribir más que la deuda más el mes en curso: para pagar meses adelantados se usa **Cobrar**.
- **Cuenta unificada:** junta los meses de todos los servicios y los cobra en un solo recibo.
- **Recibo anulado:** si se anula un recibo (por ejemplo para cargarlo de nuevo con otro monto), el recibo anulado sigue guardado con el sello rojo **ANULADO**. La oficina puede mandárselo igual al cliente con **«Enviar recibo anulado por WhatsApp»**: llega la imagen con el sello y el mensaje dice que no tiene validez, así el cliente sabe que ese recibo ya no sirve.
- **Quién no lo ve:** el técnico (no ve la deuda ni cobra mensualidades).

## Probar la conexión de un cliente (ping)

La oficina y los técnicos en la calle pueden ver si un cliente **contesta** sin tocar nada del router: en la ficha del cliente, **Conexión → Probar conexión**.

- **Cómo funciona:** el sistema (Cloudflare) no puede hacer pings. Por eso un router tuyo **consulta cada 10 segundos** si alguien pidió una prueba; si hay una, le hace **4 pings a la IP del cliente** y le avisa al sistema cuántos volvieron. La ficha lo muestra en unos segundos: **Responde** (4 de 4), **Responde con pérdidas** (1 a 3 de 4; mala señal, interferencia o un equipo que se reinicia) o **No responde** (0 de 4: apagado o sin luz, cable desconectado o servicio cortado). Si ningún router contesta en unos 45 segundos, avisa que no contestó a tiempo y se puede intentar de nuevo.
- **Qué se prueba:** solo clientes con **una sola IP** cargada en su ficha (si no tiene IP o tiene varias juntas, no aparece el botón). Nadie puede pedir el ping a una IP que no sea de un cliente cargado.
- **Quién puede:** el permiso **«Probar la conexión de un cliente (ping)»** viene encendido para oficina y técnicos; lo apagás por perfil o por usuario en Ajustes. El administrador siempre puede. Cada persona puede pedir hasta 12 pruebas por minuto.
- **Armarlo (una sola vez por router):** Ajustes → *Routers MikroTik* → en el router que va a hacer los pings → **Script de ping**. Pegá en WinBox → Nuevo terminal: (1) la prueba de conexión (si ya hiciste la de clientes, no hace falta), (2) el script (crea `yapur-ping`) y (3) la programación (cada 10 s). En unos segundos el router figura **«Pruebas de conexión: atendiendo»**. Si el router todavía no está en la lista, primero agregalo con *Agregar router* (no hace falta pegar el script de clientes si solo lo querés para pings).
- **Qué router hace cada prueba:** si el campo **Nodo** del cliente tiene el nombre de un router que atiende pruebas, lo hace ese; si no, cualquiera que esté atendiendo. Con un solo router, ese.
- **Seguridad:** el router tiene un acceso **aparte** del de la lista de clientes, que solo sirve para *consultar qué IP probar* y *devolver cuántos contestaron*: no lee nada del sistema. El script no tiene contraseñas ni toca la configuración del router (permisos `read,test`). Si lo perdés, *Script de ping* genera otro y el anterior deja de valer.
- **Consultas:** a 10 segundos son unas 8.600 consultas por día por router (cuentan para el límite del plan gratis; ver abajo). Para bajarlas, cambiá `interval=10s` por `20s` en la programación.
- **Sin probar en un router real:** el script usa `/tool fetch` y `/ping` de RouterOS 6.4x/7.x, pero **no se pudo correr en un MikroTik desde acá**. La parte del servidor y de la app sí está probada con un router simulado. Si el router dice «not enough permissions», cambiá `read,test` por `read,write,test`; si dice algo de `check-certificate`, borrá ese parámetro. Para ver qué hizo: `/log print where message~"YAPUR"`. Para apagarlo: `/system scheduler remove [find name=yapur-ping]`. No muestra los milisegundos de respuesta: solo cuántos paquetes volvieron.

## Mandar recibos desde la PC con WhatsApp Web (también en Windows 8.1)

- **Cómo:** en el recibo, **Enviar por WhatsApp**. La app copia el recibo como imagen y abre **WhatsApp Web** directo en el chat del cliente (sin la pantalla intermedia de wa.me). Hacés clic en el cuadro de mensaje, **Ctrl+V** y Enter. La pantalla del recibo lo recuerda.
- **Una sola pestaña:** todos los recibos se abren en la misma pestaña de WhatsApp Web. Si se abriera otra pestaña, WhatsApp Web pediría «Usar aquí» cada vez y apagaría la anterior.
- **Navegadores viejos (Windows 8.1):** si el navegador no puede copiar imágenes, el recibo **se descarga** como archivo PNG y se abre el chat; ahí se toca el **clip → Fotos y videos** y se elige el archivo descargado. La pantalla lo avisa.
- **Lo que no se puede:** que el recibo se mande solo desde WhatsApp Web. El navegador no deja pegar ni mandar por su cuenta (y los programas que lo fuerzan están prohibidos por WhatsApp y arriesgan el bloqueo del número): siempre es Ctrl+V + Enter. El envío automático sin tocar nada es el de la **API oficial** (el que ya usan los cobros de los técnicos).
- **Windows 8.1:** ya no recibe navegadores nuevos (la última versión de Chrome y de Edge es la 109) y la app de WhatsApp para escritorio no funciona ahí: queda WhatsApp Web. **No pude probar WhatsApp Web en ese Windows**: lo primero es abrir web.whatsapp.com en esa PC y ver que cargue y se pueda vincular con el celular.

## Recibo por WhatsApp automático (cobros del técnico)

Todo lo que cobra un técnico en la calle **genera un recibo** (con su número, a su nombre y en la caja del día) que la oficina ve en **Cobranzas → Caja del día** (cada fila dice «cobró Pedro» y abre el recibo), y **le llega solo al cliente por WhatsApp** apenas el técnico registra el cobro.

- **Qué recibe el cliente:** un mensaje de la empresa con el nombre, el monto, el concepto, el número de recibo y la fecha («Hola Ana, recibimos tu pago de $ 65.000 por Instalación. Recibo N° R261101-AB3 del 01/11/2026. Gracias por elegir YAPUR.NET.»).
- **Qué ve cada uno:** el técnico, en el recibo, lee «El recibo le llega solo al cliente por WhatsApp» (y ya no tiene el botón para mandarlo a mano, para que el cliente no lo reciba dos veces). La oficina ve en cada cobro un cartel **«WhatsApp enviado»**, **«Enviando…»** o **«WhatsApp: no se envió»**; en el recibo, a qué número y cuándo salió, o el motivo si falló, con **Reintentar envío** (y **Volver a enviar solo** si ya había salido).
- **Si no sale:** el cobro queda igual registrado. Las causas más comunes: el cliente **no tiene teléfono** (o está mal escrito: tiene que llevar código de área, sin 0 ni 15 — se prueba también el segundo teléfono), o WhatsApp rechazó el mensaje. En la caja aparece un aviso rojo con **Reintentar los que fallaron** (los que no tienen teléfono se arreglan cargando el número en la ficha y tocando *Reintentar envío* en el recibo). Ante una falla pasajera de WhatsApp el servidor reintenta solo hasta 3 veces.
- **Topes de seguridad:** hasta 3 avisos automáticos por día al mismo número y 400 en total por día (frena un uso indebido). La oficina puede reenviar a mano igual.
- **Solo los cobros del técnico** se mandan solos. Los de la oficina y el administrador siguen como siempre: botón *Enviar por WhatsApp* del recibo.
- **Apagarlo:** *Ajustes → Recibo por WhatsApp* → destildar «Mandar el recibo por WhatsApp cuando cobra un técnico». Ahí mismo está **Mandar prueba** (llega a tu celular con datos de ejemplo).
- **Lo que NO se sabe:** «enviado» significa que WhatsApp aceptó el mensaje; no se registra si el cliente lo recibió o lo leyó.

### Conectarlo (una sola vez, lo hacés vos)

Usa la **API de WhatsApp Business de Meta**. Hace falta una cuenta de empresa en Meta, un número para enviar (conviene uno que no uses en tu WhatsApp común) y una plantilla aprobada. Meta cobra un valor chico por cada mensaje, y el cliente tiene que haber aceptado recibir avisos del negocio. La pantalla *Ajustes → Recibo por WhatsApp* muestra los mismos pasos:

1. En developers.facebook.com creá una app «Empresa», agregale el producto **WhatsApp** y registrá el número. Anotá el **identificador del número de teléfono**.
2. En business.facebook.com → *Configuración → Usuarios del sistema*: creá un usuario del sistema, asignale la app y generá un **token permanente** con el permiso `whatsapp_business_messaging`. (Los menús de Meta cambian de nombre seguido; si no los encontrás, buscalos con esas palabras.)
3. En *WhatsApp Manager → Plantillas de mensajes* creá la plantilla **`recibo_cobro`**, categoría **Utilidad**, idioma **Español (Argentina)**, con este texto (el botón *Copiar el texto* de Ajustes lo copia): `Hola {{1}}, recibimos tu pago de {{2}} por {{3}}. Recibo N° {{4}} del {{5}}. Gracias por elegir YAPUR.NET.` Ejemplos que pide Meta: Ana Paz · $ 65.000 · Instalación · R261101-AB3 · 01/11/2026. Esperá a que la aprueben.
4. En **Cloudflare → Workers y Pages → yapur → Configuración → Variables y secretos** agregá dos **Secretos** (tipo *Secret*, así un nuevo despliegue no los borra): **`WA_TOKEN`** (el token) y **`WA_PHONE_ID`** (el identificador del número). Guardá/desplegá.
5. Volvé a *Ajustes → Recibo por WhatsApp*: tiene que decir **Conectado**. Mandate una prueba.

El token y el identificador **no se escriben en la app ni en ningún archivo del repositorio** y el servidor nunca los devuelve: ni el administrador los ve en pantalla. Opcionales (mismo lugar, como secretos o variables): `WA_TEMPLATE` (nombre de la plantilla si usás otro, por defecto `recibo_cobro`), `WA_LANG` (por defecto `es_AR`), `WA_VER` (versión de la API de Meta, por defecto `v23.0`).

## Cuenta unificada: una empresa con varios servicios o sucursales

Para una empresa (o una persona) con varias conexiones, por ejemplo **Manaos distribuidora** y las tres conexiones a nombre de la dueña (C. Central, suc. España y FM): **cada conexión sigue siendo un cliente** (con su domicilio, su ubicación en el mapa, su plan, su IP y su precio), pero **se cobran juntas y sale un solo recibo**.

- **Cómo se arma:** abrí la ficha de la empresa (la cuenta principal) → botón **Cuenta unificada** (al lado de Cobrar) → **Esta es la cuenta principal: sumarle conexiones** → buscás cada conexión por nombre y la tocás → confirmás. Desde la ficha de una conexión suelta, el mismo botón ofrece **Esta conexión pertenece a otra cuenta: elegir cuál**. Una vez armada la cuenta, la ficha muestra el bloque con los servicios y desde ahí se suman o se sacan. Para sacar una: en su ficha, **Sacar este servicio de la cuenta** (sigue cobrándose con el ciclo que traía y lo ya cobrado no cambia). Solo lo hace quien puede editar clientes; el técnico no ve ni cambia las cuentas.
- **La ficha** de cualquier servicio de la cuenta muestra **todos los servicios**: domicilio, plan y precio de cada uno, el total por mes y lo vencido, con botones para abrir cada ficha, **Cargar ubicación** (pegar coordenadas, un link de Google Maps o tomarla con el GPS) y **Editar domicilio**. En la lista de clientes cada servicio dice *Cuenta: Manaos distribuidora* y la principal *Cuenta · 4 servicios*; buscar «manaos» trae a los cuatro.
- **Cobrar:** *Cobrar* desde cualquiera de los servicios abre **la cuenta entera**: los meses pendientes de cada servicio, agrupados, con el mes en curso ya marcado y el total sugerido. Un pago parcial se aplica primero a lo más viejo y, dentro de un mismo mes, en el orden de la lista (la principal primero); lo que falta queda pendiente en el servicio que corresponde. Los cobros que no son mensualidad (instalación, reclamo, reconexión, deuda anterior) se registran en el servicio desde el que abriste el cobro.
- **Un solo recibo:** sale **a nombre de la cuenta principal, con su CUIT y su domicilio**, y **los servicios iguales (mismo mes y mismo precio) en un solo renglón** («Abono Mensual Servicio de Internet (noviembre de 2026) - 4 conexiones», cant. 4 × $23.000), así el recibo queda corto y entra en media hoja A4 (impreso mide unos 60 mm de alto). Si algún servicio tiene otro precio u otro mes, ese va en su propio renglón con el nombre de la conexión. El «Enviar por WhatsApp» va al número de la principal (o, si no tiene, al de alguna de las conexiones). El recibo de un solo servicio (o los recibos viejos) siguen saliendo a nombre de ese servicio, igual que antes. Todo el recibo se guarda en un solo bloque: se graba entero o no se graba.
- **Un solo ciclo:** como el recibo tiene un solo período y un solo vencimiento, **toda la cuenta sigue el ciclo de cobro de la principal** (en el formulario de cada servicio el ciclo aparece bloqueado y dice de quién lo toma). Al unir un servicio de otro ciclo la app avisa que sus fechas de vencimiento y de corte van a cambiar. Los cortes siguen siendo por conexión: cada una se corta o se reconecta por su cuenta.

## Dispositivos: saber desde qué equipos entra cada persona

El sistema registra **cada teléfono o navegador desde el que alguien entra con su usuario** (modelo y sistema, si es la app o el navegador, IP, lugar aproximado, primer y último uso) y **no deja entrar a un empleado desde un equipo que el administrador no aprobó**.

- **Dónde se ve:** Ajustes → **Dispositivos** (solo el administrador). Primero aparecen los que esperan aprobación, después los autorizados (el último uso arriba) y al final los bloqueados.
- **Equipo nuevo de un empleado (técnico u oficina):** entra la clave bien, pero no recibe sesión: la pantalla le dice que el equipo no está autorizado y le muestra un **código de 6 letras**. Al administrador le aparece un aviso arriba («1 equipo pide entrar…») y el equipo en la lista, con ese mismo código para reconocerlo. **Aprobar** → el empleado vuelve a tocar «Entrar» y pasa. **Bloquear** → no puede volver a entrar.
- **Bloquear o quitar un equipo** cierra su sesión en el acto (la pantalla abierta vuelve sola a «Entrar»). Se puede **Permitir de nuevo** uno bloqueado.
- **Con la clave de un técnico desde otro equipo** (por ejemplo, un celular ajeno): no entra; queda como pendiente con su modelo, IP y operador, para que lo rechaces.
- **El administrador** nunca necesita aprobación; sus equipos nuevos quedan anotados en la lista, para que veas si alguien entró con tu usuario.
- **Se puede apagar** el pedido de aprobación en esa misma tarjeta (los equipos nuevos entran solos pero igual quedan en la lista).
- **Al actualizar:** las sesiones que ya estaban abiertas siguen funcionando y aparecen como **Sesión anterior**; en cuanto ese teléfono usa la app nueva se completa con su modelo real. Las que no reconozcas, **Quitar**.
- **Límites:** la app también es un link web, así que no se puede impedir que alguien la abra o la «instale»: lo que se controla es quién **entra**. Un empleado ya aprobado puede mostrar la app en su propio teléfono. La ubicación sale de la IP: en datos móviles muestra la ciudad del operador. Cada equipo se identifica con un código que guarda la app en el propio teléfono: si borran los datos de la app o instalan de nuevo, el equipo aparece como nuevo y hay que aprobarlo otra vez.

## DNI, CUIT y CUIL

El campo se llama **DNI / CUIT / CUIL** en el formulario, la ficha, los recibos, el permiso y los buscadores. Un CUIT o CUIL se puede escribir como sea (`27 23373806 4`, `27-23373806-4`, `27233738064`): se guarda ordenado, **27-23373806-4**, y mientras lo escribís avisa si el dígito verificador no coincide (un número mal tipeado); un DNI se deja como lo escribas. Al **buscar** funciona con o sin guiones. Al **importar**, además de *DNI*, *CUIT* y *CUIL* se reconocen encabezados como *DNI / CUIT* o *D.N.I / CUIT* (como en tu planilla), y en el **reporte del técnico** también se acepta «CUIT:».

## Importar la lista de clientes (Excel) y el recibo con tu formato

- **Importar clientes:** *Ajustes → Importar clientes (CSV)*. Además de las columnas de siempre, ahora lee **velocidad** (elige el plan cuya bajada coincide: 2,5 · 3,5 · 5 · 10…), **cobrar desde** (por cliente: `2026-11` o `11/2026`), **ciclo** (1 o 2) y **precio especial**. Si el precio del archivo es igual al del plan, no se guarda como precio especial (así los cambios de precio del plan siguen llegando a esos clientes); si es distinto, sí. Una velocidad que no tiene plan se avisa antes de importar: esos clientes quedan sin plan pero se cobran igual por su precio.
- **Cobrar desde:** quien ya pagó el mes en curso entra con el mes siguiente; quien no pagó entra con el mes en curso y figura debiendo. No se arrastran meses anteriores.
- **Los que ya estaban:** si el nombre coincide (sin importar mayúsculas, tildes ni el orden de las palabras) no se vuelven a crear. Con **Completar** tildado se les llenan solo los datos que les faltaban (DNI, teléfono, plan, nodo, notas…); no se pisa nada de lo que ya tenían, y el ciclo y «cobrar desde» solo se tocan si el cliente todavía no tiene pagos. Importar dos veces la misma lista no duplica a nadie.
- **Subir precios en bloque:** *Ajustes → Clientes y cobranzas → Subir precios en bloque*. Elegís «pagan hasta $17.000, desde $10.000, pasan a $18.000, desde noviembre» y te muestra cuántos cambian antes de aplicar. Los meses anteriores conservan el precio viejo (queda como vigencia en cada cliente), no toca a los de abonos chicos (solo TV, adicionales), ni a los que digan «solo tv» en las notas, y se puede correr de nuevo sin cambiar a nadie dos veces. Si el plan del cliente ya vale el precio nuevo, el precio especial se saca y lo da el plan.
- **Clientes sin plan:** si al importar avisa «Velocidades sin plan», creá esos planes en *Planes* (la velocidad de bajada tiene que coincidir) y volvé a importar el mismo CSV con **Completar** tildado: les asigna el plan, y si su precio especial es igual al del plan, lo saca.
- **Precios de instalación:** *Ajustes → Precios de instalación* (solo el administrador). Ver «Cobros del técnico».
- **Datos del recibo:** *Ajustes → Datos del recibo* (nombre comercial, razón social, CUIT, Ingresos Brutos, domicilio, teléfonos, web, punto de venta y alias de pago). Se cargan una vez y salen en todos los recibos, como en el recibo de papel: ORIGINAL · NO VÁLIDO COMO FACTURA, punto de venta y número, cliente, condición de venta, período facturado y vencimiento, tabla con el concepto cobrado, importe total y alias. Se puede copiar, mandar por WhatsApp o **imprimir** (desde la computadora). El número del recibo sigue siendo el código de la app (fecha + letras).
  - **Período facturado y vencimiento:** el período va **del día en que empieza el ciclo del cliente hasta ese mismo día del mes siguiente**, y el pago **vence el día de vencimiento del ciclo, en el mes siguiente**. **Ciclo 1** (noviembre de 2026): *desde 01/11/2026 hasta 01/12/2026 · Vto. para el pago: 10/12/2026*. **Ciclo 2**: *desde 13/11/2026 hasta 13/12/2026 · Vto. para el pago: 20/12/2026*. (Los días salen de los ciclos de *Ajustes*.) Si se cobran varios meses juntos, va del comienzo del primero al comienzo del mes que sigue al último. Esto es solo lo que dice el recibo: no cambia cuándo se considera vencida una deuda ni cuándo se corta.
  - **El plan no sale en el recibo** (ni el nombre del plan ni los servicios adicionales); solo el concepto cobrado.
  - **«Enviar por WhatsApp» manda el recibo como imagen**, igual que el papel (no un texto largo). En el **APK** abre WhatsApp directo en el chat del cliente con la imagen adjunta (hace falta el APK nuevo; con uno anterior se manda el texto como antes). **La primera vez con cada número** WhatsApp no sabe todavía de ese chat y lo abre vacío, sin la imagen: por eso la app abre primero el chat y, apenas volvés con la flecha «atrás», abre el recibo listo para mandar; las veces siguientes con ese número va directo. En el navegador del celular abre el menú de compartir con la imagen. En la computadora **copia la imagen** y abre el chat: se pega con Ctrl+V. Si algo de eso no se puede, se manda el texto como antes: el envío nunca se pierde. Los recibos que salen solos por la API de Meta (técnico) no cambian.
  - **Reenviar y reimprimir cuando quieras:** en la **ficha del cliente → Últimos pagos** (los últimos 12) cada pago es tocable y abre **su recibo**, con *Enviar por WhatsApp*, *Copiar recibo* e *Imprimir*; sirve para mandar un recibo que nunca se mandó o volver a imprimirlo. También se abre desde *Cobranzas → Caja del día*. Los recibos anulados también se abren (llevan el sello ANULADO y no se mandan).
  - **Imprimir desde el celular (APK):** *Imprimir* abre la impresión de Android con el recibo en media hoja A4: se elige la impresora o **«Guardar como PDF»** (para compartirlo). Hace falta el APK nuevo: con uno anterior avisa que hay que actualizar. En la computadora imprime por el navegador.
  - **Impresión en media hoja A4:** el recibo se imprime arriba de una hoja A4, ocupa menos de 148 mm de alto (un mes ≈ 95 mm; seis meses ≈ 137 mm) y se corta la hoja al medio; sale con la letra más chica y la tabla completa.

## Dónde están los técnicos (horario laboral)

La pestaña **Técnicos** muestra, para cada técnico, cuándo fue la última vez que mandó su posición, su precisión, el recorrido del día y dos botones: **Ver en el mapa** (abre Maps en su última posición) y **Recorrido del día** (ruta aproximada en Maps). Hay un selector de día para mirar los anteriores. La ve el administrador y quien tenga el permiso **«Ver dónde están los técnicos»** (Ajustes → Perfiles).

**Cómo saber si un técnico dejó de mandar** (se ve sin instalar nada nuevo):
- Cada técnico tiene un cartel de estado: **En línea** (mandó hace 10 minutos o menos), **Sin señal · hace N min** (pasaron más de 10 minutos; en rojo si pasó más de una hora), **Todavía no mandó su posición** (hoy, dentro del horario, no llegó nada), **Fuera de horario** o **Todavía no aceptó el aviso**.
- Arriba aparece un cartel amarillo con **quiénes están sin señal ahora** y desde cuándo, y esos técnicos suben al principio de la lista. La pestaña se actualiza sola cada minuto mientras se mira el día de hoy.
- **Tramos sin señal:** en cada técnico, «Sin señal 1 h 20 min en 3 tramos» se despliega con la lista de horarios (por ejemplo «10:05 a 10:48 · 43 min»). Cuenta como tramo todo silencio de **más de 10 minutos** dentro del horario, incluido el del arranque («antes de su primera posición») y el que todavía sigue abierto. Vale para cualquier día guardado (14 días). Si un día no tiene ningún punto, no se inventa un tramo: puede ser un día libre.
- **Avisarle por WhatsApp:** cuando está sin señal o todavía no mandó nada, el botón abre el chat del técnico con el mensaje ya escrito («…la oficina no recibe tu ubicación desde las 10:05. Abrí la app…»). Hace falta que tenga el teléfono cargado y el permiso para ver teléfonos. No se manda solo: lo enviás vos.
- Un silencio no siempre es culpa del técnico: celular apagado, sin datos o Android durmiendo la app (ver «Batería» más abajo).

Cómo funciona, para que sea claro y justo con quien trabaja en la calle:
- **Solo en horario laboral: de 8 a 20 h** (hora de Argentina). El horario lo controla el servidor con su reloj: lo que llega fuera de ese rango se descarta aunque el celular lo mande. El administrador lo cambia con **Cambiar el horario**.
- **Horario de corrido o cortado (con siesta).** Un día puede tener un tramo (de corrido, ej. 8 a 20) o dos (cortado, ej. **8 a 13 y 17 a 22**). En **Técnicos → Cambiar el horario**: se carga el de corrido, se tilda «También hay días con horario cortado», se cargan la mañana y la tarde y se tildan **qué días de la semana** se trabaja cortado (los demás quedan de corrido). Para **un día puntual** (por ejemplo un día de mucho calor) se elige la fecha y «cortado» o «de corrido» y gana sobre el día de la semana; el botón **«Hoy: cortado / de corrido»** de la pestaña Técnicos cambia solo el de hoy con un toque. Hay que cargar los dos tramos antes de poder marcar días cortados, y la mañana tiene que terminar antes de que empiece la tarde. Las horas son enteras.
  - **La siesta no cuenta como «sin señal»:** los tramos sin señal se miran tramo por tramo, y entre la mañana y la tarde el técnico figura «Fuera de horario». El servidor no guarda nada entre tramos. Si a la tarde se pasan 10 minutos de la hora de retomar sin recibir nada, recién ahí aparece «Sin señal».
  - **Jornada en un día cortado:** el *ingreso* es el primero de la mañana (se compara con el «desde» de la mañana), y se anota además la **retoma**: la primera vez a la tarde que el celular aparece en la base (*Retomó 17:03*, en amarillo si pasa la tolerancia, y *No retomó a la tarde* en rojo con un cartel arriba si no aparece). Entre los dos tramos figura **En siesta**, y el *fin* del día es el último regreso a la base de la tarde; en esos días no se muestra «jornada de X horas» porque incluiría la siesta.
  - Si el técnico vuelve a la base al mediodía y no a la tarde, o retoma sin haber ido a la base, la retoma queda vacía: el control mira dónde estuvo el celular, igual que el resto.
- **Cada técnico acepta un aviso** la primera vez que entra («Ubicación en horario laboral»): dice el horario, quién la ve y que se borra. Si dice «Ahora no», no se manda nada. Mientras comparte, ve el cartel **Ubicación activa** arriba.
- **Un punto por minuto** como máximo (el servidor no guarda más de uno cada 20 segundos) y **se borra a los 14 días**. No entra en las copias de seguridad.
- Solo los usuarios de tipo **Técnico** comparten ubicación. La oficina y el administrador no.
- **En Chrome** la posición se manda **mientras la página está abierta**. **En el APK (2.4 o posterior)** un servicio propio la manda también **con la pantalla apagada**; Android obliga a dejar una notificación mientras un servicio usa la ubicación (no se puede quitar); desde el **APK 2.12 o posterior** es la más discreta posible (**importancia mínima**: sin sonido, **sin ícono en la barra de arriba**, abajo de todo en el panel y oculta en la pantalla bloqueada; dice solo «Gestión YAPUR · Ubicación compartida de 8 a 20 h»). Los canales de notificación viejos no se pueden cambiar desde la app, por eso se crearon canales nuevos y el viejo («ubicacion») se borra solo. Lo único que sigue sonando bajito es el aviso de **GPS apagado o sin permiso**, a propósito. **En un día cortado, con el APK 2.6 o posterior el servicio queda en pausa durante la siesta** (no le pide nada al GPS) y retoma solo a la hora de la tarde. Con un APK anterior a la 2.4 sigue valiendo lo de Chrome.
- **Siempre activo, sin abrir la app (APK 2.7 o posterior).** El servicio ya no se corta al terminar el día ni cuando se cierra la app: queda **«en espera»** (notificación discreta, sin tomar nada del GPS) y **empieza solo a la hora del horario de cada día**, aunque el técnico no haya abierto la app esa mañana. Así el ingreso y el fin de la jornada se anotan solos. El servicio le pide el horario del día al servidor (de corrido, cortado, días puntuales) con la sesión del técnico, y si no hay conexión usa el último que conoce. **Vuelve solo** al prender el celular, al actualizar la app y, con una alarma de control cada 15 minutos, si Android lo cerró. Se detiene cuando el técnico **cierra sesión** o si el servidor dice que la sesión ya no vale. Para poder volver solo, **la sesión del técnico queda guardada en la memoria privada de la app** (no se puede leer desde otras apps ni entra en copias de seguridad de Android); se borra al cerrar sesión.
  - **Hace falta una vez por celular:** abrir la app, entrar con el usuario del técnico y aceptar el aviso (que ahora dice que se comparte también con la app cerrada; quien ya había aceptado el aviso de antes ve **uno aparte** al abrir la app nueva: si dice «Ahora no», sigue como antes), y darle a la app el permiso de ubicación **«Permitir todo el tiempo»**. Desde Android 11 no es un cuadro: el botón **Activar** abre la pantalla de permisos de la app y ahí elige «Ubicación → Permitir todo el tiempo». Mientras no lo dé, arriba queda un cartel amarillo **«Activar ubicación “todo el tiempo”»** y se le vuelve a ofrecer una vez por día.
  - **Sin ese permiso** el servicio igual sigue todo el día si arrancó con la app abierta, pero **si el celular se reinicia o Android lo cierra, no puede volver solo a leer el GPS** hasta que el técnico abra la app (en horario de trabajo le aparece una notificación «tocá para activar tu ubicación» que, al tocarla, abre la app).
- Al instalar el APK nuevo, Android pide al técnico el permiso de ubicación (**«Mientras se usa la app»**, ubicación precisa), en Android 13 o posterior el de notificaciones y, con el APK 2.7, el de **«todo el tiempo»** (ver arriba). Fuera del horario no se toma ni se guarda nada, aunque el servicio esté en espera.
- **Cortar el GPS de un técnico a mano** (solo el administrador). Cuando el regreso a la base no se detectó solo, en la pestaña **Técnicos**, en la tarjeta de ese técnico (solo «hoy» y si ya aceptó el aviso), el botón **«Cortar GPS»** pide **a qué hora se fue** (por defecto, ahora; no puede ser futura ni anterior al comienzo del horario de hoy). Qué hace:
  - Desde esa hora el servidor **descarta** todo lo que mande ese técnico, **borra** lo que ya había guardado desde entonces, y esa hora queda como el **fin de su jornada de hoy** (se anota un regreso en esa hora; las horas trabajadas llegan hasta ahí). Si la oficina ya había cargado las horas a mano, eso manda y no se toca. Si el técnico todavía no tenía ingreso hoy, solo se corta el GPS.
  - **Es solo de hoy**: mañana arranca normal. La tarjeta muestra «GPS cortado a las HH:MM», la jornada «Terminó HH:MM · GPS cortado a mano» y el tramo posterior no cuenta como «sin señal».
  - **El celular del técnico se entera**: con la app abierta le llega en vivo (evento `ubic` por el WebSocket) y el cartel dice «Ubicación cortada por la oficina»; el servicio del APK ya instalado vuelve a pedir su horario cada 10 minutos y ahí recibe el horario **recortado** (`tramos` con la hora del corte redondeada para arriba, porque el APK lee solo horas enteras) y deja de mandar. Mientras tanto lo que mande se descarta (la respuesta trae `cortado: true`). No hace falta un APK nuevo: el corte nunca devuelve «no aplica» ni «sin aceptar», que son los casos en que el servicio se apaga para siempre.
  - **«Reanudar GPS»** (mismo botón) lo vuelve a habilitar desde ese momento; lo ya borrado no vuelve, y el fin de jornada queda donde estaba hasta que el técnico mande posiciones nuevas.
  - Se guarda en `meta` como `ubiccorte:<id del técnico>:<AAAA-MM-DD>` (se limpia a los 90 días). Rutas: `POST /api/ubicacion/cortar {uid, ts?}` y `POST /api/ubicacion/reanudar {uid}`, solo administrador. Pruebas: `tests/test_corte.js` y `tests/e2e_corte.py`.
- **Batería:** el GPS cada minuto durante el día gasta más batería. Con el **APK 2.5 o posterior**, la primera vez que arranca el servicio el celular le pregunta al técnico si deja la app **«sin restricción de batería»** (cuadro del propio Android: tiene que tocar **Permitir**). Es lo que más evita que Android duerma o cierre la app con la pantalla apagada. Si dice que no, se le vuelve a preguntar a los 3 días. En algunos celulares (Xiaomi, Samsung, Motorola…) además conviene revisar a mano en Ajustes → Aplicaciones → Gestión YAPUR → Batería que diga **«Sin restricciones»** y, en Xiaomi/Huawei, permitir el «inicio automático». En Android 14 o posterior el técnico puede quitar la notificación deslizándola; el servicio sigue, y el cartel «Ubicación activa» de la app lo confirma.
- **Por qué quedó «sin señal» (el «latido») y la alerta de 15 minutos.** Cuando dejan de llegar posiciones, la tarjeta del técnico ahora dice el **«Motivo probable»**, según lo que le contó el propio celular:
  - **Cada minuto, solo dentro del horario**, la app manda un **latido**: si la ubicación del celular está prendida (GPS y red), si la app tiene el permiso de ubicación y cuánta batería queda (`POST /api/ubicacion/latido`). **No lleva ninguna posición.** El servidor lo ignora fuera del horario o con el GPS cortado, y guarda solo el último latido y los tramos en que la ubicación estuvo apagada o sin permiso (`meta`: `ubiclat:<técnico>` y `ubicev:<técnico>:<día>`; se borran a los 14 días).
  - **Motivos posibles** (cuando está «sin señal»): *tiene la ubicación del celular apagada desde HH:MM* · *la app no tiene permiso de ubicación desde HH:MM* · *la app responde y la ubicación está prendida, pero el celular no da posiciones* (lugar cerrado o mala señal de GPS) · *la app dejó de responder a las HH:MM* (cerrada, celular sin datos o apagado; **no se puede saber cuál de las tres**) · *se quedó sin batería* (dejó de responder con la batería en 5 % o menos). El servidor no inventa ningún motivo puntual cuando no llegó **ningún** latido en ese tramo (APK viejo, o app que nunca se abrió) — en ese caso la tarjeta muestra, en su lugar, la explicación genérica más común: que no tiene instalada la app YAPUR Gestión y está usando el sitio en el navegador, donde la ubicación se corta en cuanto se bloquea la pantalla o se cambia de app, con el recordatorio de instalarla y dejar el permiso en «Permitir todo el tiempo» y «sin restricción de batería».
  - La tarjeta suma **«Ubicación apagada o sin permiso N min en K tramos»** (con la hora de cada uno, aunque ahora esté en línea: sirve para ver si la apaga y la prende), **a cuánto de la base** estaba su última posición («en la base» o «a 3,4 km de la base») y el botón *Avisarle por WhatsApp* ya trae el pedido que corresponde («prendé la ubicación», «dale el permiso a la app»…).
  - **Alerta para vos:** quien tiene el permiso «Ver dónde están los técnicos» ve, con la app abierta, un **contador rojo en la pestaña Técnicos** y una **barra arriba, en cualquier pestaña**, cuando alguien lleva **15 minutos o más sin señal dentro del horario** (con el motivo corto). La barra se puede **ocultar 30 minutos** (vuelve si cambia quién está sin señal) y se va sola al entrar a la pestaña. Se consulta cada minuto (cada 10 fuera de horario): `GET /api/ubicaciones/alerta`, una pregunta liviana que no baja posiciones.
  - **Transparencia con el técnico:** el aviso que se acepta ahora dice que la oficina también ve si la ubicación o la app están apagadas y la batería. A quien **ya había aceptado** el aviso de antes le aparece arriba un cartel con eso mismo y el latido **recién empieza cuando toca «Entendido»** (en el APK nuevo, el servicio no manda nada hasta que la página se lo confirma: `activarLatido`). Nada de esto se toma fuera del horario.
  - **APK:** el latido propio del servicio (que sale también con la app cerrada y avisa en el momento de apagar la ubicación) viene en el **APK que arma GitHub después de este cambio** (la versión sube sola). Mientras un técnico tenga el APK anterior, o use Chrome, manda el latido **la página, y solo con la app abierta**: ahí el «sin motivo» o «dejó de responder» es lo esperable. **El APK nuevo hay que instalarlo en los celulares** (aparece el aviso «Hay un APK nuevo»). Pruebas: `tests/test_ubic.js` (servidor y motivos) y `tests/e2e_latido.py` (pantallas); la parte de Android se verificó que compila contra Android 6 (API 23) pero **no se pudo probar en un celular real**.
- **Qué no se puede garantizar** (hay que saberlo, y **no se pudo probar en un celular real desde acá**):
  - Si el técnico **fuerza el cierre** de la app (Ajustes → Aplicaciones → Gestión YAPUR → *Forzar detención*), Android desactiva todo hasta que la abra de nuevo: ni el servicio ni el aviso de arranque funcionan.
  - **Xiaomi, Huawei, Oppo, Vivo, Realme y algunos Samsung** cierran las apps en segundo plano por su cuenta. Además de «sin restricción de batería», en esos celulares hay que activar a mano el **«inicio automático»** (o «autoarranque») y, en Samsung, sacar la app de «aplicaciones en suspensión». Es una vez por celular; si no, el servicio puede morir de noche y no volver.
  - Desde **Android 12** el sistema limita arrancar un servicio de ubicación desde segundo plano. Con **«todo el tiempo»** concedido, el arranque al prender el celular y la alarma de control están previstos y deberían funcionar; si Android igual lo rechaza, queda la notificación «tocá para activar». La oficina lo ve en la pestaña **Técnicos** («Sin señal» o «Todavía no mandó su posición») y puede avisarle por WhatsApp.
  - El **primer minuto del día** puede atrasarse unos minutos si el celular está quieto, apagado de pantalla y en ahorro profundo (Android demora las alarmas). Para que el *ingreso* no figure tarde por eso, conviene que el «Desde» del horario sea **un rato antes** de la hora de llegada.
  - **Nada que corra en el celular es a prueba de alguien decidido a esconderse**: apagar el celular, dejarlo en la base o en la casa, usar otro, sacarle los datos, forzar el cierre de la app. «Sin señal» **no prueba por sí solo** que esté en su casa: puede ser cobertura, batería o un celular que Android durmió (por eso el sistema dice «motivo probable» y no acusa). Lo que sí deja es **evidencia**: a qué hora dejó de responder, dónde estaba la última vez y cuántas veces apagó la ubicación en el día. **Lo que no se puede esquivar es un GPS puesto en el vehículo** (un rastreador conectado a la batería del vehículo, escondido y con su propia SIM): sigue andando aunque el técnico apague el celular, y es lo que corresponde para saber **dónde están los vehículos de la empresa**. El sistema se puede conectar a uno de esos (por ejemplo, con un servidor Traccar) si decidís comprarlos.
- Si el técnico no dio el permiso de ubicación del celular, ve «Ubicación sin permiso» y en la pestaña figura «Todavía no mandó su posición».

## Bloqueo de la app si falta la ubicación (horario laboral)

**Solo durante el horario laboral de hoy**, un técnico que no está compartiendo su ubicación **no puede usar la app para nada**: se le muestra una pantalla sin forma de cerrarla (no hay pestañas, no hay vuelta atrás) que explica qué falta y cómo solucionarlo. No se aplica a la oficina ni al administrador, y fuera de horario no se exige nada (es la misma regla de siempre: «fuera del horario no se toma ni se exige nada»).

Se bloquea solo por algo que el propio técnico decidió o le falta, **nunca por una señal de GPS débil o momentánea** (eso sería injusto: un lugar cerrado o un bache de señal no debe dejarlo sin poder cargar un pago o cerrar una orden). Los tres motivos posibles, y lo que ve:
- **Todavía no aceptó el aviso** de compartir ubicación (dijo «Ahora no», o se cortó la conexión al guardarlo): ve el mismo aviso de siempre con el botón **«Entendido, aceptar»**.
- **Le sacaron el permiso de ubicación** al navegador o a la app: ve «Falta el permiso de ubicación» con un botón para revisarlo de nuevo (y, en el APK, uno que lleva directo a los ajustes de la app).
- **Tiene la ubicación del celular apagada** (GPS y red): solo se puede saber con certeza **en el APK** (el navegador no distingue «apagada» de «sin señal todavía»), con un botón **«Prender ubicación»** que lleva directo a la pantalla de Android para prenderla.

**Se destraba sin recargar la página.** Al aceptar el aviso, se destraba al toque. Con el GPS (solo APK), se destraba solo: el chequeo propio vuelve a preguntarle a Android cada pocos segundos. Con el permiso del navegador, hace falta tocar **«Ya lo di: revisar de nuevo»** después de arreglarlo (el navegador no avisa solo cuando un sitio recupera un permiso; por eso no se le vuelve a preguntar todo el tiempo). No es a prueba de alguien decidido a esquivarlo (puede cerrar la app y no abrirla), pero si la quiere usar, tiene que tenerla prendida.

**El motivo «GPS apagado» necesita el APK que arma GitHub después de este cambio** (trae un aviso nuevo, `ubicEstado`, que le pregunta a Android con certeza si el permiso y la ubicación están dados). Con un APK anterior, o en Chrome, siguen funcionando igual los otros dos motivos (aviso y permiso), pero el de «GPS apagado» no se puede detectar y no bloquea por eso. Pruebas: `tests/e2e_bloqueo.py`.

## Control de ingreso y fin del día (jornada)

Anota **solo**, sin que el técnico toque nada, a qué hora empezó y a qué hora terminó el día, mirando si el celular está en la base (donde guardan los vehículos). No hace falta APK nuevo. **Viene apagado:** mientras no se cargue la base no se anota nada, no hay alarmas ni barra en el celular del técnico.

**Cómo se arma** (administrador): pestaña **Técnicos → Base y jornada**. Parado **en el galpón donde se guardan los vehículos** (no en el local de adelante: el pin de Google Maps del negocio queda a unos metros del galpón), al aire libre y quieto, tocá **«Usar mi ubicación actual (GPS)»** y guardá. Toma unas 10 lecturas (hasta 20 s) y las promedia dando más peso a las más precisas; esperá a que diga **±10 m o menos** (con más de ±15 m avisa que es poco precisa y conviene repetir en un lugar más abierto). Se ajustan el **radio** (40 m por defecto; de 20 a 2000), la **tolerancia** para llegar (10 min) y los **días de trabajo** (lunes a sábado; los demás días no cuentan como falta). La hora esperada de ingreso es el **«Desde»** del horario de ubicación (por defecto las 8).
- **Ingreso:** la primera posición del día dentro del radio de la base. La hora es la de esa posición (el servidor no acepta horas de más de 15 minutos atrás).
- **Fin:** cada vez que el celular sale de la base y vuelve a entrar se anota un **regreso**; el **último regreso del día** es el fin. Si vuelve a salir, deja de figurar como terminada hasta que regrese. Para que un punto de GPS pegado al borde no cuente como entrar y salir, se «sale» recién a 1,5 veces el radio.
- **Ingreso a mano:** si un técnico arranca sin pasar por la base, toca **«Iniciar jornada»** en la barra de arriba. Queda marcado como **manual**, con la distancia a la base, para que se vea.

**Qué ve el técnico:** una barra arriba, siempre visible: «Tu jornada laboral comenzó a las 08:47 · en la base» y, al volver, «…y terminó a las 18:05 al volver a la base (9 h 18 min)». La primera vez muestra un aviso con **«Más info»** y **«Entendido»** (queda constancia de que lo vio; el registro funciona igual aunque no lo toque).

**Qué ve la oficina** (Técnicos, con el selector de día): *Ingresó 08:47 · 47 min tarde* (pasada la tolerancia, en amarillo), *Terminó 18:05 · jornada de 9 h 18 min*, *Sin ingreso* en rojo, un **cartel arriba con quiénes no ingresaron hoy** (esos técnicos suben al principio de la lista) y, en días anteriores, *No volvió a la base*. El atraso se mide contra el «Desde» del horario.

**Límites, para no esperar de más:**
- **Con el APK 2.7 y el permiso «Permitir todo el tiempo» no hace falta abrir la app:** el servicio queda andando y manda la posición solo en el horario (ver «Dónde están los técnicos»). **En el navegador o con un APK anterior sí**: la app tiene que estar abierta (al menos una vez en el día) para que el celular mande su posición; sin eso no hay dato y figura «Sin ingreso».
- Registra **dónde está el celular**, no si la persona trabajó: un celular olvidado en la base seguiría figurando en la base.
- **Qué tan justo es:** la hora de ingreso tiene una exactitud de **±1 minuto** (el celular manda una posición por minuto), y el lugar, la del GPS del teléfono: **entre 5 y 15 m al aire libre**, bastante peor bajo techo. Por eso el radio de 40 m: más chico que eso, un celular parado adentro del galpón puede figurar «afuera» cuando el GPS se corre. Si pasa, subilo a 60.
- Una posición cuya precisión es peor que el radio (o que 50 m, lo que sea mayor) **se ignora**: ni cuenta como entrar ni como salir. Así una lectura mala bajo techo no genera un ingreso o un regreso falsos.
- **Después de volver a la base la ubicación se sigue compartiendo hasta el final del horario** (de corrido, hasta las 20 h; cortado, hasta el final de la tarde); no se corta sola al terminar. Si no querés ver el camino a casa del técnico, bajá el «Hasta» del horario.
- Se guardan **90 días**, y solo la hora, el origen (base o manual) y la distancia a la base: **no se guardan coordenadas** en este registro. No entra en las copias de seguridad, igual que la ubicación.

## Horas trabajadas (para pagar por hora)

Sale de la jornada de arriba, sin cargar nada: no hace falta APK nuevo. En **Técnicos → Horas trabajadas** ves, por técnico, **una casilla por día** de la semana (lunes a domingo, en horas:minutos) y el **total de la semana**. Con las flechas pasás a otras semanas (hasta 90 días atrás). Tocando una casilla ves el detalle del día: los tramos y cómo se contó. Abajo, **«Copiar el resumen»** (para pegarlo en WhatsApp) y **«Descargar CSV»** (una fila por día, con las horas en h:mm y en decimal, por ejemplo 8,50, y el total de cada técnico).

**Cómo se cuenta un día:** desde que el celular llega a la base (el ingreso) hasta la última vez que vuelve a ella. Si sale a trabajar y vuelve a la base, ese rato **cuenta** (es tiempo de trabajo). En un día **cortado** se cuenta cada tramo por separado y **la siesta no se cuenta**: la mañana va del ingreso a la última vez que estuvo en la base antes del corte (o hasta el final del tramo, si cortó sin pasar por la base), y la tarde, de la retoma a su último regreso.

**Los días que hay que mirar:**
- **Sin cerrar** (amarillo): el técnico ingresó pero no se lo vio volver a la base (se quedó sin batería, cerró la app, no pasó por la base). Se cuenta hasta la última posición recibida, que puede ser menos de lo que trabajó. Hay un cartel arriba con la cantidad de días así.
- **En curso** (verde): el día de hoy, que sigue sumando.
- **Corregido** (con asterisco): lo cargó la oficina a mano.

**Corregir un día** (solo el administrador): tocás la casilla → **«Corregir las horas»** y cargás a qué hora empezó y terminó (un par de horas por tramo), con el motivo, que queda anotado junto con quién lo cambió. Sirve también para cargar un día en el que no hubo registro. Lo que cargues **reemplaza** el cálculo automático de ese día; con **«Volver al cálculo automático»** se saca la corrección y vuelve lo que midió el celular (no se pierde nada).

**Qué ve el técnico:** en la barra de arriba, **«Hoy 5 h 10 min · semana 21 h»** y el botón **«Mis horas»** con cada día de la semana. Si un día figura «Sin cerrar» o no le cierra, le avisa a la oficina. No puede corregir nada. Los demás perfiles de oficina no ven las horas salvo que tengan el permiso de ver técnicos.

**Límites, para no pagar de más ni de menos:**
- Es el tiempo que **el celular estuvo reportando** entre el ingreso y el último regreso a la base, no una prueba de que la persona trabajó: un celular olvidado, o un técnico que se queda en el galpón, sigue sumando. Por eso conviene revisar el resumen antes de pagar.
- Si el horario de ubicación termina antes de que el técnico vuelva a la base (por ejemplo, el horario es hasta las 20 y vuelve a las 20:30), ese regreso **no se registra** y el día queda «Sin cerrar». Conviene que el «Hasta» del horario sea más tarde que el fin real de la jornada.
- Las horas se guardan **90 días**, igual que la jornada, y no entran en las copias de seguridad: **descargá el CSV de cada semana o quincena al liquidar**.
- La exactitud de cada hora es la de la jornada (±1 minuto en la hora y los metros del GPS del teléfono).

## Cliente nuevo desde el reporte del técnico

En **Clientes → Nuevo cliente**, arriba, está **Completar con el reporte del técnico**: pegás el texto que manda el técnico por WhatsApp y toca **Completar los datos**.

```
NOMBRE: Ana Ester Paz
DNI: 28354900
IP: 10.20.43.9
PAGO: (Efectivo) 65mil pesos que es el costo de instalación
```

- Lee `NOMBRE`, `DNI`, `IP` y `PAGO`; también `TELÉFONO`, `DIRECCIÓN`, `LOCALIDAD` y `PLAN` si vienen. Ignora los emojis y los renglones en blanco.
- Deja al cliente **activo** y con «cobrar desde» el **mes siguiente** (se puede cambiar). Avisa qué falta completar (el teléfono y la calle son obligatorios) y si ya hay otro cliente con ese DNI o esa IP.
- Si trae un pago («65mil», «65 mil pesos», «$65.000»…), al guardar se abre **Cobrar** ya completado: concepto (instalación, o reclamo si dice «reclamo» o «visita»; una reconexión se carga como «Otro»), medio (efectivo, transferencia o Mercado Pago) y monto. Hay que confirmarlo con «Registrar cobro».
- El cobro queda a nombre de quien lo registra. Si la plata la tiene el técnico y tiene que figurar en su caja, que lo cargue él desde su celular con «Cobrar instalación o reclamo».

## Planes de noviembre (un solo botón)

En **Planes**, si faltan, aparece el aviso **Cargar planes de noviembre**: crea de una vez **Plan 100** ($18.000) y **Plan 200** ($19.000) de 15 Mbps, y **Plan 20 Mbps** ($23.000), **Plan 25 Mbps** ($24.000) y **Plan 30 Mbps** ($35.000). Las velocidades y la ráfaga salen de las colas de los routers (ráfaga = velocidad + 10M, umbral 8M, 22 s, garantizada 256k de subida y 1M de bajada). Si ya existe un plan con ese nombre, no se duplica ni se toca. Después se editan como cualquier plan (el precio con «rige desde»).

De dónde salen: en los 4 routers (Admin, FM, Leo, Bomberos; 729 colas al 31/10/2026) casi todo es 15M/15M con ráfaga 25M (Plan 100 y Plan 200 comparten velocidad, solo cambia el precio) y hay un segundo nivel 25M/25M con ráfaga 35M; el resto son casos sueltos (20M, 30M, 40M, 50M…) que se cargan con «precio especial».

Cuando los de noviembre ya están cargados y los clientes ya se pasaron a ellos, el mismo lugar ofrece **Desactivar planes sin clientes**: deja de ofrecer los planes viejos que nadie usa. No se borran; se reactivan desde «Editar».

**Eliminar un plan:** Planes → el plan → *Editar* → **Eliminar plan** (solo el administrador). Se puede únicamente si **ningún cliente lo usa**: ni los activos, ni los dados de baja, ni en el historial de precios de un cliente (un cliente que antes tuvo ese plan lo conserva ahí para que los meses viejos y la deuda anterior no cambien de precio). Si alguien lo usa, el formulario lo explica («figura en 12 clientes») y no muestra el botón; el servidor también lo rechaza. En ese caso lo que corresponde es **destildar «Plan disponible para clientes nuevos»**: deja de ofrecerse y todo lo cargado sigue intacto. Eliminar no se puede deshacer, pero queda en las copias de seguridad diarias.

## Cómo se arma lo que paga cada cliente: plan + servicios

El total mensual es **el plan de internet + cada servicio adicional** (por ejemplo Plan 100 + Multimedia + Multimedia Net). Los precios de los servicios se cambian en la pestaña *Planes*, sección *Servicios adicionales* (solo el administrador). El **precio especial** reemplaza **solo la parte de internet**: los servicios se suman aparte. Por eso:
- Cliente con Plan 100 y Multimedia: plan = Plan 100, servicio = Multimedia, precio especial vacío. Cobra lo que vale el plan + lo que vale Multimedia.
- Si ese cliente tiene un descuento en internet, el precio especial es **solo el internet con descuento**, no el total con el servicio. Si cargás el total, el servicio se cuenta dos veces.
- Cliente que paga solo un servicio (TV, adicionales): plan «Sin plan» y el servicio tildado.
- Para controlar la caja del mes: el **Resumen** muestra la *Facturación mensual de activos* y, abajo, cuántos clientes tiene cada plan y cada servicio con su total.

## Asignar planes y servicios a los clientes ya cargados

En **Ajustes → Importar clientes (CSV)** tildá **Actualizar el plan, los servicios y el precio de los que ya están cargados** y elegí desde qué mes rigen (por defecto el siguiente). El archivo necesita la columna `nombre` y, según lo que quieras cambiar, `plan`, `servicios` y `precio especial`.
- Se buscan por nombre (sin importar el orden de las palabras). **No se crean clientes nuevos**: las filas sin coincidencia se cuentan aparte y se saltean.
- `plan` con el nombre exacto del plan (creálo antes en Planes). `Sin plan` deja solo los servicios. `servicios` admite varios: `Multimedia + Multimedia Net`.
- `precio especial` es **solo la parte de internet** (los servicios se suman aparte). Vacío = que cobre el precio del plan. Si es igual al del plan, se saca solo.
- Una fila sin plan ni servicios no toca a nadie. Lo que tenía cada cliente queda guardado hasta el mes anterior, así los meses viejos y la deuda anterior conservan su precio.
- Antes de confirmar ves cuántos cambian, por plan.

## Servicio sin cargo: tu casa, la de tus padres (no deben nada ni se cortan)

Hay abonados que usan el servicio pero no pagan: la casa del dueño, la de la familia. Se marcan como **Servicio sin cargo** y el sistema los trata así:

- **No generan deuda**: no tienen meses vencidos ni importe a pagar, aunque nunca hayan pagado nada. Figuran siempre como **«Sin cargo · Al día»**.
- **No aparecen entre los morosos**, ni en «Con deuda», ni en el Resumen (deuda vencida); como no están en esas listas, tampoco tienen el botón de avisar la deuda por WhatsApp.
- **No aparecen en «A cortar»**, ni en «Marcar suspendidos» ni en el script de MikroTik de la lista de cortes. Cuando se automatice el corte de los morosos, tiene que saltearse a todo cliente con la marca `sinCargo` (la pantalla «A cortar» ya lo hace).
- Siguen contando como **clientes activos** (son clientes reales, con router y todo), pero **no suman a la facturación mensual** del Resumen. Se los encuentra con el filtro **«Sin cargo»** de la lista de clientes.
- Al abrir «Cobrar» de uno de ellos, avisa que no se le cobra mensualidad.

**Quién lo hace: solo el administrador.** En *Editar cliente → Facturación* aparece el casillero **Servicio sin cargo** (y un motivo opcional, por ejemplo «Casa de Mauro», que solo ve el administrador). La oficina y los técnicos no ven el casillero y el servidor rechaza el cambio aunque lo intenten por otro camino; la oficina sí ve que el cliente es «sin cargo» (para no perseguirlo por una deuda), pero no el motivo, y el técnico no ve nada de esto. La oficina puede seguir editando la ficha del cliente sin perder la marca.

Dos cuidados al usarlo:

1. **Marcar a un cliente que hoy debe**: el formulario avisa cuánto debe y que esa deuda deja de contarse. Si en realidad corresponde cobrársela, cobrala antes de marcarlo.
2. **Sacarle la marca**: se vuelve a cobrar **desde ese mes** (el campo «Cobrar desde» pasa al mes actual), así no aparecen de golpe meses viejos como deuda. Si querés cobrar desde otro mes, cambialo en el mismo formulario.

## Empezar a cobrar de cero y «Deuda anterior»

**Ajustes → Clientes y cobranzas → Empezar a cobrar de cero.** Elegís el mes desde el que se cobra (por defecto el siguiente) y la pantalla te cuenta cuántos clientes se mueven y cuánto suman las deudas. Al confirmar, todos los clientes activos y suspendidos pasan a «cobrar desde» ese mes: ninguno figura como moroso ni «A cortar» por meses anteriores.

Lo que cada uno debía hasta ese momento **no se pierde**: queda anotado como **Deuda anterior** (los meses sin pagar, al precio que tenían). Es un saldo aparte:
- No genera cortes ni aparece en «Morosos». Se cobra cuando el cliente pueda.
- Se ve como chip «Deuda anterior · $…» en la lista y en la ficha, con el detalle de los meses.
- **Cobranzas → Deuda anterior** lista a todos (los que más deben primero), con el total por cobrar, botón **Cobrar** y **Recordar por WhatsApp**. El Resumen muestra el total y lleva a esa lista.
- **Cobrar deuda anterior** acepta pagos parciales y emite recibo («Deuda anterior: Octubre de 2026»). Si se anula el cobro, la deuda vuelve.
- En la ficha, **Editar → Facturación** permite cargar o corregir la deuda a mano (por ejemplo una que estaba anotada en las notas), y **Dar por saldada** la perdona.

**Sin deuda anterior:** tildá **«No dejar deuda anterior: perdonar lo que debían»** y nadie queda debiendo nada: los meses sin pagar no se anotan y la deuda anterior que ya estuviera cargada se da por saldada (a todos, incluso a quienes ya empezaban ese mes). La pantalla cuenta cuánto se perdona antes de confirmar. **No se puede deshacer**, por eso viene sin tildar. Los cobros ya hechos y los recibos no se tocan.

Correrlo dos veces no mueve a nadie dos veces. Los clientes que ya empiezan ese mes o después, los «por instalar» y los de baja no se tocan.

## Avisos de actualización

- **App nueva (la mayoría de los cambios):** cuando se publica una versión nueva en Cloudflare, quien tenga la app abierta (o la abra) ve arriba **«Hay una versión nueva de la app»** con el botón **Actualizar**. Revisa al abrir, al volver a la app y cada 10 minutos. No hace falta reinstalar el APK.
- **APK nuevo (solo cuando cambia la parte de Android, por ejemplo un permiso nuevo):** el celular ve **«Hay un APK nuevo (2.X) con mejoras»** con el botón **Descargar**, que abre la descarga en el navegador. Se instala encima, sin perder nada. Lo informa el archivo `yapur-version.json` que publica solo el flujo que compila el APK.
- «Después» esconde el aviso hasta que se vuelva a abrir la app.

## Copias de seguridad

- El sistema guarda **solas 2 copias por día** (la primera escritura del día y otra 8 horas después) y conserva las últimas 28 (14 días). **Ajustes → «Copias automáticas…»** las lista y permite volver a una (antes de restaurar guarda una copia del estado actual, por si te arrepentís).
- Además, **Ajustes → «Descargar copia completa»** baja un archivo a tu celular/PC. Convendría bajarlo una vez por semana y guardarlo fuera de Cloudflare.

## Qué hay que saber del plan gratis de Cloudflare

- Alcanza de sobra para ~2.000 clientes y un equipo chico: el límite es de 100.000 pedidos por día y un uso normal ronda unos pocos miles.
- Las **pruebas de conexión** suman unas 8.600 consultas por día por cada router que las atiende (cada 10 segundos). Con uno o dos routers sigue sobrando; con muchos, subí el intervalo a 20 s o pasá al plan pago.
- **El tope que se alcanzó el 5/11/2026:** además de los pedidos, el plan gratis limita el **tiempo que la base de datos está encendida por día** (13.000 GB-s; el error dice «Exceeded allowed duration in Durable Objects free tier»). Antes la conexión en vivo de cada pantalla (SSE, con un aviso cada 20 segundos) la mantenía encendida las 24 horas apenas hubiera una app abierta, y ese día se agotó: sin servicio hasta el reinicio de las 21:00 hs. Ahora las pantallas se conectan por **WebSocket con hibernación**: la base de datos se duerme mientras nadie hace nada y despierta cuando hay un cambio que avisar (el «ping» de cada pantalla lo contesta Cloudflare solo). Si una red bloquea los WebSocket, la app vuelve sola al SSE de antes (que sí mantiene encendido el servidor). Las versiones viejas de la app siguen funcionando por SSE. Si igual se llegara al tope, el servidor contesta el motivo (503) en vez del «Error 1101»; pasar al plan pago (USD 5 al mes) lo elimina.
- Si alguien inundara la dirección con pedidos basura, se podría agotar ese cupo y el sistema se detiene hasta las 21:00 hs de Argentina (00:00 UTC). No es un riesgo de datos (no se pierde nada), pero sí de servicio. Mientras tanto, la app abre con lo último que bajó y se puede consultar sin conexión.
- Si el negocio crece o querés más tranquilidad, el plan pago de Workers cuesta unos USD 5 por mes y elimina ese tope.
- Los ingresos tienen bloqueo por intentos fallidos (5 por usuario y dirección, 25 por dirección), guardado en el servidor.
- El código de instalación solo sirve mientras no exista ningún administrador; después queda inutilizado.

## Cómo se probó

Se probaron de punta a punta, contra el servidor real de Cloudflare simulado en la computadora (`wrangler dev`, mismo motor `workerd`): permisos de cada perfil, que cada usuario vea solo lo suyo, cobranzas que no se pueden borrar ni editar, ciclos de facturación 1–10 y 13–20 con feriados, promesas de pago, servicios extra, tiempo real entre usuarios, bloqueo por intentos, copias de seguridad y restauración, reinicios del servidor, la app en modo celular con navegador Chromium (sin conexión incluida) y los avisos de actualización y el botón del GPS con ubicaciones simuladas (precisa, que afina sola, floja, sin permiso, y al cerrar una instalación) y la red (alta de cajas y empalmes con el GPS, orden por cercanía, conexión del cliente a su caja y puerto, permisos y borrados bloqueados).

**No se pudo probar** en este entorno: el programa de Android en un celular real (incluido el permiso, la lectura real del GPS y el servicio de ubicación con la pantalla apagada, que depende de cada marca y versión de Android) (se verificó que el APK se arma, firma y alinea bien y que el manifiesto declara el servicio como corresponde, pero no hay emulador), la publicación real en Cloudflare ni la corrida real en GitHub Actions. Si algo falla en alguno de esos tres pasos, es lo primero que hay que mirar.

Para volver a correr las pruebas: `cd yapur-app/tests && npm install && npm test` (GitHub también las corre en cada pedido de cambios, con `probar-yapur.yml`).

## Para quien mantenga el código

- `app/src/` es el código de la aplicación; `node yapur-app/app/build.js` lo arma en `worker/public/` (que es lo que publica Cloudflare). Si se cambia `src` y no se arma, la prueba `test_build.js` falla a propósito.
- `worker/src/worker.js` es el servidor (un Worker + una base SQLite dentro de un Durable Object).
- `android/` es el APK (sin Gradle, mismo método que FAVL): `build_apk.sh`.
- Los secretos de firma (`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`) son los mismos que ya usa FAVL; no hay que cargar nada nuevo.
